# 模板库：实现计划（第 2 块）

日期：2026-11-20 · 设计：`docs/superpowers/specs/2026-11-20-projects-templates-skills-design.md` 第 3 节

**目标：** 设置里有“模板”页。用户提前准备 bot 模板（一个角色）和团队模板（一个负责人加若干成员），之后建项目时选团队模板。

**做法：** 模板存在 `<数据目录>/templates/` 下，每个模板一个文件夹，用现有的模板文件夹格式（`bot.md` 或 `team.md`，加 `skills/` 和 `avatars/`）。现有格式不带的内容写在旁边的 `magicbot.json` 里。读写、导出、检查都用现有代码，不另写一套。

**状态：** 已做完。下面的“任务”全部完成，最后一节是需要用户确认的决定。

## 先查清的事：现有格式带什么，不带什么

查的是 `shared/package-format.ts`（唯一的检查关口）、`shared/share-folder.ts`（文件夹读写）、`server/share.ts`（共享导出）。

| 内容 | 现有格式 | 模板库放哪里 |
|---|---|---|
| 角色的名字、职责（一行）、说明、人设、外观（颜色、表情、身体、头像图片） | 带（`agents[]`） | `bot.md` / `team.md` |
| 角色的标识 `key` | 带（`agents[].key`，允许下划线） | 同上；模板库只用小写字母、数字和短横线 |
| 模板自带的技能和它们旁边的文件 | 带（`skills/<名字>/`） | `skills/` |
| 团队的背景说明 | 带（`team.brief`，最多 24000 字节） | `team.md` |
| 负责人 | 带（`team.leader`） | `team.md` 和 `magicbot.json` 各记一份，以 `magicbot.json` 为准 |
| 角色的初始记忆 | 带（`agents[].seed.memory`，`MEMORY.md` 加主题文件） | `team.md` / `bot.md` |
| 群聊、例行任务 | 带（`rooms`、`routines`） | 原样保留，页面不编辑 |
| 模型 | **不带**（格式里没有这个字段） | `magicbot.json` |
| 技能库里的技能（只记名字） | **不带** | `magicbot.json` |
| MCP 服务（按名字） | 不带名字。格式里的 `connections` 是地址，共享导出时还会去掉 | `magicbot.json` |
| 适合什么题材 | 不带 | `magicbot.json` |
| 版本号、保存时间 | 不带（`release` 是给发布用的） | `magicbot.json` |
| 脸的颜色、头像图片的缩放和位置 | 不带 | `magicbot.json` |
| 头像图片 | 只带 PNG、JPEG、WebP，每张最多 64 KB | `avatars/` |
| 不认识的字段 | **丢掉**（zod 的对象检查默认去掉多余字段） | 所以额外内容不能写进 `team.md` |

共享导出（`server/share.ts` 的 `templateDocument`）还会去掉：初始记忆、连接地址、批准级别、密钥样子的文字。所以“把现有机器人存成模板”得到的模板没有记忆，也没有密钥。

## 这一块定下的细节

1. **目录。** `templates/bots/<编号>/`、`templates/teams/<编号>/`，删掉的在 `templates/archive/removed/` 下。编号是程序生成的 16 位十六进制，直接当文件夹名。
2. **`magicbot.json`**：`schema`、`kind`、`version`、`updatedAt`，团队模板另有 `genre`、`lead`、`retiredKeys`；`roles` 按角色标识记 `model`、`librarySkills`、`mcpServers`、`look`。
3. **`magicbot.json` 坏了或没有**：模板照样列出来，版本取 `team.md` / `bot.md` 里 `release` 的第一段（没有就算 1），没有模型、技能库引用和 MCP 设置，负责人取 `team.md` 里的，再没有就取第一个角色。这样一个用现有“导入/导出”拿来的模板文件夹放进去也能用。模板文件夹本身读不出来时，只跳过这一个模板，其余照常列出。
4. **角色标识。** 小写字母、数字和短横线，最多 40 个字符，一个模板里不重复。新角色的标识由名字生成：名字里有英文或数字就用它们，否则是 `role-1`、`role-2`。保存后不再变。一个角色被移除后，它的标识记在 `retiredKeys` 里，以后的新角色不会拿到它。
5. **版本号。** 新建是 1，每保存一次加一。
6. **名字。** 模板名最多 60 个字符、只能一行、同类模板里不重复（不分大小写）。团队模板里角色名不重复。
7. **技能的两种带法。** 技能库里的技能只记名字；模板自带的技能存在模板的 `skills/` 里，建项目时复制给机器人。一个团队模板里同名的自带技能只有一份。
8. **模型和 MCP 可以不选。** 不选模型，建项目时用默认模型；不选 MCP，机器人沿用现有行为（用所有已开启的服务）。
9. **初始记忆按角色记。** 现有格式就是按角色带初始记忆的（建好后写进这个机器人的 `MEMORY.md`），所以放在角色上。全团队都要知道的内容写在背景说明里。
10. **删除**不弹确认，删除后可以“撤销”。文件夹移进归档目录，不真正删除。
11. **从 bot 模板挑成员**：页面把 bot 模板读出来，复制一份进团队模板（连同它自带的技能），之后两边互不影响。
12. **把现有机器人或部门存成模板**用现有的共享导出生成内容（去掉密钥、记忆和聊天），再从机器人现在的设置里补上模型、技能库引用和 MCP 服务。部门的负责人成为模板的负责人，部门的背景说明成为模板的背景说明。
13. **谁能改。** 模板是整个安装共用的，只有所有者或管理员能改；页面在简单模式和高级模式下都有。

## 接口

服务器里的其他部分用 `TemplateLibraryApi`（只读）；页面的路由和 `template-sync` 用 `TemplateLibraryEditor`（在它之上加了写的部分）。两个都在 `shared/template-library.ts`。

```ts
export interface TemplateLibraryApi {
  list(): TemplateLibraryWire;
  readTeam(id: string): TeamTemplateContent | null;   // 给“建项目”用：document 直接交给 importPackageDocument
  readBot(id: string): BotTemplateContent | null;
}

export interface TemplateLibraryEditor extends TemplateLibraryApi {
  botTemplate(id: string): BotTemplateWire | null;
  teamTemplate(id: string): TeamTemplateWire | null;
  saveBot(input: unknown, id?: string): BotTemplateWire;      // 不带 id 是新建，带 id 是存成下一版
  saveTeam(input: unknown, id?: string): TeamTemplateWire;
  remove(kind: TemplateKind, id: string): { undo: string };
  restore(undo: string): { kind: TemplateKind; id: string };
  saveFromBot(botId: string): BotTemplateWire;
  saveFromDepartment(department: string, into?: string): TeamTemplateWire;   // into：存成那个模板的下一版
  addStarterMemory(kind: TemplateKind, id: string, role: string, text: string): void;
}
```

`TeamTemplateContent` 里：`document` 是现有包格式的团队，每个角色一个 agent，`key` 就是角色标识；`extras` 按角色标识记模型、技能库技能名、MCP 服务名和外观的补充；`lead` 是负责人的标识；`version` 是版本号。

HTTP（都在 `/api/template-library` 下，全部只给管理员）：

- `GET /api/template-library`：`TemplateLibraryWire`（和其他人约定好的）。
- `GET /bots/:id`、`GET /teams/:id`：`{ template }`，一个模板的全部内容，给编辑器用。
- `POST /bots`、`POST /teams`：新建，201。`PUT /bots/:id`、`PUT /teams/:id`：保存，版本加一。
- `DELETE /bots/:id`、`DELETE /teams/:id`：返回 `{ ok, undo }`。`POST /restore`，内容 `{ undo }`。
- `POST /bots/from-bot`，内容 `{ botId }`；`POST /teams/from-department`，内容 `{ department }`。

## 已知的缺口和风险

1. **两个人同时改同一个模板**：后保存的覆盖先保存的，没有提示（保存时不核对“我是从第几版改起的”）。模板只有所有者和管理员能改，碰上的机会小。要补的话，保存时带上版本号，对不上就拒绝。
2. **不留旧版本**（决定 5）。删除可以撤销，但“撤销”只在那几秒的提示里；之后被删的模板一直留在 `templates/archive/removed/` 里，没有界面能翻出来，也不会自动清理。
3. **按名字记的东西不检查还在不在**：模型、技能库技能、MCP 服务都只记名字。技能库里已经没有的技能，编辑器里有标注；模型和 MCP 服务用的是机器人设置里现成的卡片，对已经不存在的名字怎么显示，我没有验证。建项目时遇到不存在的名字怎么办，是 `projects` 那一部分的事。
4. **配对的手机读不到模板**（决定 16）。
5. **中文名的角色，标识是 `role-N`**，项目文件夹里看到的也是它（决定 2）。
6. **沿用的两处文字不贴切**（决定 20）：“头衔”的占位文字，和上传图片下面的“GIF · 最大 10 MB”。
7. **自带的技能不能在编辑器里新写**（决定 11）。
8. **`server/share.test.ts` 有 1 个失败**，要等集成合并 `lab-contract-rename-tests-2`（见上面“检查”）。
9. **`shared/settings-places.ts` 是生成的文件**：别人也加了设置项的话，合并之后要重新生成，否则设置的测试会失败。

## 需要用户确认的决定

设计没有定、我自己定下来的事。每条写的是：问题、我的选择、理由、以后想改有多难。排在前面的更值得看一眼。

### 一、模板里存什么

**1. 初始记忆是整个团队一份，还是每个角色一份？**
- 选择：每个角色一份。全团队都要知道的事写在“背景说明”里。
- 理由：现有的模板格式就是按角色带初始记忆的，建项目时直接写进那个机器人的 `MEMORY.md`，不用新造一套。
- 改起来：中等。要加一个团队级的字段，还要定下建项目时这份记忆写给谁。

**2. 角色的标识（项目里那个机器人的文件夹名）由谁来定？**
- 选择：程序自动生成，页面上不显示也不让填。角色名里有英文字母或数字就用它们（`Script writer` → `script-writer`），否则是 `role-1`、`role-2`……所以中文名的角色都是 `role-N`，项目文件夹里看到的也是这个名字。之后改名，标识不变。
- 理由：标识要当文件夹名，限制多（小写、不能和别的角色重复、不能是 Windows 的保留名），让人填容易出错；页面也因此简单。
- 改起来：加一个输入框很容易。但已经存下的标识不能再改，因为用它建出来的项目里，文件夹就叫这个名字。

**3. 一个角色被移除后，它的标识能不能给新角色用？**
- 选择：不能。团队模板记着它用过、现在已经没有的标识（`magicbot.json` 里的 `retiredKeys`，最多记最近 200 个），新角色跳过它们。同一个角色用原来的标识回来时，就从这个名单里去掉。
- 理由：“同步”是按标识把项目里的机器人和模板里的角色对上的。不这样做的话，把“选书”删掉再加一个“配音”，“配音”会拿到“选书”原来的 `role-2`，老项目里那个“选书”机器人就会被当成“配音”来更新。
- 改起来：容易（只是一个名单）。

**4. 模板能不能重名？**
- 选择：同一类里不能（不分大小写）。在编辑器里起了重名会被拒绝，并提示换个名字。从机器人或部门“存为模板”时不拒绝，自动在名字后面加序号（“短剧一部 2”）。
- 理由：主 bot 和“新建项目”都是让人按名字选团队的，重名就分不清了。“存为模板”是在菜单里点一下，没有地方让人改名，所以自动加序号。
- 改起来：容易。

**5. 保存之后，旧版本还留不留？**
- 选择：不留。保存就是覆盖，版本号加一。
- 理由：设计只要求版本号，没有要求能回到旧版；“同步”需要的是“项目用的是第几版、模板现在是第几版”。
- 改起来：中等。保存前把旧文件夹放进归档目录就能留住，但还要做查看和取回的界面。

**6. 撤销删除时，如果这期间又建了一个同名的模板怎么办？**
- 选择：不放回，并告诉用户“现在已经有一个同名的模板了”。被删的那个还在归档目录里。
- 理由：不能有两个同名模板，也不该悄悄改名。
- 改起来：容易。

**7. 模型和 MCP 服务是不是必须选？**
- 选择：都可以不选。不选模型，建项目时用当时的默认模型；不选 MCP 服务，机器人用所有已经开启的服务（和现在的机器人一样）。
- 理由：模板是提前准备的，那时候不一定知道以后用哪个模型；不逼人做一个可能很快过时的选择。
- 改起来：容易。

**8. 头像图片怎么存？**
- 选择：现有格式每张图最多 64 KB、只收 PNG、JPEG、WebP。所以页面把选中的图片自动缩到 512 像素以内，转成 WebP（浏览器不支持就转成 JPEG）。选的是 GIF 时只留第一帧，变成一张不动的图。形状选了“吉祥物”的角色，保存时不带图片。
- 理由：用现有格式就得守它的上限；头像在界面上本来就显示得很小。直接拒绝大图或 GIF 的话，用户得自己去找工具缩图。
- 改起来：难。要放宽就得改现有的模板文件夹格式，那会影响“共享”和“导入导出”。

**9. 把部门存成团队模板时，部门里的群聊和例行任务怎么办？**
- 选择：一起存下来，原样保留；页面上只显示数量（“群组聊天 2 个，例行任务 1 个”），不能在模板页里编辑。bot 模板不带例行任务。
- 理由：这是现有共享导出本来就带的内容，丢掉可惜；但给它们做编辑界面超出了这一块的范围。
- 改起来：中等（要做编辑界面）；想改成不带则很容易。

**10. 哪些技能会被复制进模板，哪些只记名字？**
- 选择：机器人自己私有的技能复制进模板（“自带的技能”）；技能库里的技能只记名字；“这台电脑上的技能”不复制也不记。
- 理由：这就是设计里“技能的两种带法”。这台电脑上的技能属于电脑，不属于某个机器人。
- 改起来：容易。

**11. 自带的技能能不能在模板编辑器里新写？**
- 选择：不能。自带的技能只能随“把机器人存为模板”带进来；在编辑器里能看到、能移除。没有任何角色用的自带技能，保存时丢掉。
- 理由：写技能已经有技能库和机器人自己的技能页，再做一个技能编辑器是重复的。想让多个项目共用，应该放进技能库。
- 改起来：中等（要在编辑器里接上现有的技能编辑界面）。

**12. 从 bot 模板复制一个角色进团队时，它自带的技能和团队里已有的技能重名怎么办？**
- 选择：保留团队模板里已有的那一份。
- 理由：一个团队模板里同名的自带技能只能有一份；已经在的那份可能正被别的角色用着，不该被悄悄换掉。
- 改起来：容易。

**13. 上限定多少？**
- 选择：每类最多 200 个模板；一个团队最多 30 个角色；模板名 60 个字；题材 2000 个字；背景说明 24000 字节（现有格式的上限）；每个角色最多引用 100 个技能库技能和 100 个 MCP 服务；整个模板不超过 4 MB。
- 理由：都比正常用得到的大得多，只是为了挡住失控的输入。
- 改起来：容易（除了背景说明的 24000 字节，那是现有格式定的）。

**14. `magicbot.json` 丢了或坏了，版本号怎么办？**
- 选择：版本号同时写在模板文件自己的 `release` 字段里（`3.0.0` 表示第 3 版），`magicbot.json` 读不出来时从那里取。
- 理由：项目记着自己是从第几版建的，版本号倒退会让“同步”判断错。
- 改起来：容易。

**15. 共享导出会去掉一些内容（密钥、记忆、聊天、连接地址），要不要逐条告诉用户？**
- 选择：不告诉。
- 理由：这些本来就不该进模板；逐条列出来只会让人以为出了问题。
- 改起来：容易（导出的结果里有这份清单）。

### 二、谁能用，在哪里

**16. 谁能看、能改模板？**
- 选择：只有所有者或管理员。模板页、侧栏里的两项“存为…模板”，别的成员都看不到；所有模板接口在服务器的请求关口上都只给管理员。配对的手机也读不到模板列表。
- 理由：模板是整个安装共用的，改一个会影响以后所有用它建的项目。
- 改起来：容易。要让手机能选模板，在允许清单里加一行就行。

**17. 模板页放在哪里，简单模式下有没有？**
- 选择：设置里单独一页（内部编号 `templates`），排在“你和你的机器人”后面。简单模式和高级模式下都有，内容完全一样。简单模式的设置导航因此从 10 项变成 11 项。
- 理由：设计说“设置里有模板页”；建项目在两种模式下都能用，那准备模板也应该都能用。
- 改起来：容易。

**18. “存为模板”放在哪里？**
- 选择：机器人菜单的“更多”里，排在“复制”后面，叫“存为机器人模板”；部门菜单里，排在“共享”后面，叫“存为团队模板”。点了之后直接保存，然后打开设置的模板页，新模板就在列表里。失败时显示在应用平时的错误提示里。
- 理由：任务要求放在机器人和部门原有的菜单或共享操作旁边。存完马上能看到结果，比只弹一句“已保存”清楚。
- 改起来：容易。

### 三、页面怎么用

**19. 编辑器长什么样？**
- 选择：一个对话框。团队模板左边一列是“团队”和各个角色（负责人有标记），右边是选中那一项的内容；bot 模板只有角色的内容。窄窗口里这一列变成顶上的一行，可以横着滑，“添加角色…”始终看得见。两种模式下用同一个布局，不隐藏任何东西。
- 理由：角色多的时候，一长页往下滚很难找；这个布局和设置窗口本身一致。
- 改起来：中等。

**20. 角色那一页放哪些东西、按什么顺序？**
- 选择：形象（点“更换形象”才展开）、名称、头衔（一行，写这个角色做什么）、简介、人设、模型、技能、MCP 服务、初始记忆。形象、头衔、简介、人设、模型、MCP 服务直接用机器人设置里现成的那几块，文字也沿用它们的。技能是新写的一张小卡片：从下拉框里选技能库的技能，下面列出已选的和自带的，每个都能移除。初始记忆是一个输入框。
- 理由：任务要求复用现有的编辑器和选择器，用户在机器人设置里已经认识这些东西。机器人设置里的技能页要对着一个真的机器人才能用（装技能、开关技能都是马上生效的），模板里的角色还不是机器人，所以这一块没法照搬。
- 改起来：容易（调顺序）。沿用来的文字里有两处和模板页不太贴：“头衔”的占位文字写的是“描述你的智能体做什么”；上传图片下面的小字写的是“PNG、JPEG、GIF 或 WebP · 最大 10 MB”，而模板里实际存下来的是缩小后的不动的图。都是原有的文字，按规定不能改，我没有动。

**21. “人设”那一栏叫什么？**
- 选择：“人设（SOUL.md）”。
- 理由：设计里把它叫“人设”；机器人设置里同一栏叫“长期指示（SOUL.md）”。模板页用设计里的词，再带上文件名，认得 SOUL.md 的人一眼知道是同一个东西。
- 改起来：容易（一条文字）。

**22. 关闭编辑器时有没保存的改动，要不要问？**
- 选择：不问，直接关。页面上出现几秒钟的提示：“‘某某’的修改没有保存 · 继续编辑”，点了就回到刚才的内容。
- 理由：`DESIGN.md` 不允许确认弹窗，要用“撤销”代替。
- 改起来：容易。

**23. 编辑到一半离开设置（比如去加一个 MCP 服务），内容还在不在？**
- 选择：在。正在编辑的内容放在页面之外的一个小状态里，回到模板页时编辑器还开着。关掉应用就没有了。
- 理由：给角色选 MCP 服务时，常常要先去另一页加一个服务。
- 改起来：容易。

**24. 在编辑器里移除一个角色或一个自带技能，要不要确认？**
- 选择：不确认，出现“已移除‘某某’ · 撤销”。
- 理由：同上，`DESIGN.md` 的规定。
- 改起来：容易。

**25. 什么时候能点“保存”？**
- 选择：新模板要有名字，每个角色都要有名字，背景说明不超过 24000 字节；缺什么，对话框底部会写出来。已有的模板只有改过才能点“保存”（改了又改回去也算改过）。
- 理由：每保存一次版本号加一，不该因为没改东西的保存白白涨版本，那会让项目以为模板更新了。
- 改起来：容易。

**26. 列表里每一行显示什么？**
- 选择：名字、“第 n 版”，团队模板再加一行角色名（负责人后面标“负责人”）。不显示头像。
- 理由：选模板时最需要的是名字和里面有谁。
- 改起来：容易。

**27. 技能库里已经删掉的技能，角色上还显示吗？**
- 选择：显示，旁边注明“技能库里没有这个技能”，可以移除。
- 理由：悄悄去掉的话，用户不知道这个角色少了一个技能；技能也可能以后又放回技能库。
- 改起来：容易。

**28. 没选模型时页面怎么显示？**
- 选择：显示“新建项目时，使用当时的默认模型”，下面一个“指定模型”按钮；点了从应用现在的默认模型开始选。选过之后有“改用默认模型”可以清掉。
- 理由：让“没选”成为一个看得见的、正常的状态。
- 改起来：容易。

**29. 题材那一栏的提示怎么写？**
- 选择：“写清楚这个团队适合哪些题材，给项目挑团队时就看这段话。”不提“主 bot”。
- 理由：界面上还没有“主 bot”这个词，提了用户反而不明白。
- 改起来：容易（一条文字）。

**30. 新加的角色是什么颜色？**
- 选择：自动用一个团队里还没人用的颜色；都用过了就从头轮。
- 理由：不然新角色全是同一个颜色，在侧栏里分不清。
- 改起来：容易。

**31. 葡萄牙语里“团队”用哪个词？**
- 选择：equipe。
- 理由：现有的葡萄牙语文字里“团队”已经是这个词。
- 改起来：容易。

### 四、给别的部分留的接口

**32. 把部门“存回”一个已有的模板时，保留什么？**（`template-sync` 用的 `saveFromDepartment(部门, 模板编号)`）
- 选择：保留模板的名字、题材、各角色的标识，以及标识没变的角色的初始记忆。负责人取部门的 Chief，没有就取模板原来的负责人，再没有就取第一个角色。机器人是从哪个角色建出来的，就存回那个角色。
- 理由：共享导出不带记忆和题材，直接覆盖会把模板里人工写的这些内容冲掉。
- 改起来：容易。

**33. 往模板的初始记忆里“沉淀”一段内容，算不算一次保存？**（`addStarterMemory`）
- 选择：算，版本加一；内容追加在原有记忆后面，另起一段。空内容什么都不做。
- 理由：模板变了，用它的项目应该能看到有新版本。
- 改起来：容易。

**34. 为 `template-sync` 扩展了接口。**
- 选择：应协调人的要求，在 `TemplateLibraryEditor` 里加了上面两个方法。页面自己的 HTTP 接口 `POST /teams/from-department` 没有跟着扩展（它只新建）。
- 理由：`template-sync` 在服务器里直接调用，不经过 HTTP。
- 改起来：容易。

### 五、动了别人文件的地方

**35. 头像组件 `Avatar.tsx` 加了 `HeldAvatarPictures`。**
- 选择：让头像能显示编辑器里刚选、还没保存到任何地方的图片。
- 理由：模板里的角色不是真的机器人，没有可以取图片的地址；不加这个就得另写一个头像组件。
- 改起来：容易。

**36. `place-banner.ts` 的缩图函数可以传入上限。**
- 选择：图片的边长和文件大小的上限可以传进去，另有一个“GIF 取第一帧”的开关。默认值都不变，横幅图片的行为和以前一样（仍然不收 GIF）。
- 理由：复用现有的缩图代码，不另写一份。
- 改起来：容易。

**37. 设置的几份清单、两个侧栏菜单、四个测试里钉死的清单。**
- 选择：各加一项，其余不动。详见上面“给集成的说明”。
- 理由：新页面和新菜单项必须出现在这些清单里。
- 改起来：容易。

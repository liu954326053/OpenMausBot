# 去掉团队连线和环节判定：实现计划（pb-lines 轨道）

日期：2026-11-24 · 设计：`docs/superpowers/specs/2026-11-24-production-board-design.md` 第 3 节 · 章程：`OpenMausBot-wt/BOARD-CHARTER.md`

**目标：** 团队图上的连线、画线、成员环节判定、建团队时规划环节全部去掉。联系规则在团队里和项目里一样：负责人能联系每一位成员（项目里包括每集的 bot），其他成员能联系负责人；旧数据里画过连线的团队和没画过一样，`team-flows.json` 和判定留下的文件留在数据目录里，不读也不删。项目负责人的提示词讲清楚：先在群聊里和人确认需求，再调用一次 `production_plan`，之后系统自动接力，出了问题会告诉他，他再跟进。

## 这一块定下的细节

### 服务端

- 删 `server/team-flow/`、`server/team-judge/`、`shared/team-flow.ts`、`server/team-flow.e2e.test.ts`。`server/peer-roster-flow.test.ts` 里仍然成立的用例搬到新的 `server/peer-roster-leads.test.ts`，其余随文件删掉。
- `server/index.ts` 只删不加：team-flow 的 import 和路由、`startTeamJudge`、`list_bots` 回答里的 `flowRelation`、`flowPlace`、`pipelineRosterWire`，`resolveTeammate` 不再传"交活还是提问"。
- `server/peer-roster.ts` 回到没有流水线时的规则：团队项目是一道墙（项目里的 bot 互相能联系，还能联系主 bot；主 bot 只联系各项目的负责人），部门不是墙。去掉 `flowAllows`、`flowRefusal`、`pipelineTeam`、上下游标记、流水线的说明和名册；`reachesOnlyHere` 只看是不是项目里的 bot。每集的 bot 是项目里的 bot，不在群聊里也一样联系得到。
- `server/chief-of-staff.ts` 去掉 `pipelineReachRule` 和按流水线排的名册。项目负责人多一段制作的说明：先在项目群聊里和人确认需求，再调用一次 `production_plan`；之后系统自己派发和接力，任务失败、某一集停下、全部完成时都会告诉他，他再跟进。
- `list_bots`（`server/drivers/agents-call.ts`）不再讲流水线。
- `propose_team_setup` 只定成员和负责人：工具说明和参数去掉 `stages`；`server/team-setup-requests.ts` 去掉取出环节、确认卡上的流水线一行和建好后记环节；带 `stages` 的计划按未知字段拒绝。golden 重新生成，预算基线变化在 2% 以内，不动。
- `server/side-jobs.ts` 去掉 `team-judge`；假引擎去掉判定那次调用；`scripts/ci-scope.mjs` 去掉删掉的测试；`server/user-errors.ts` 和各语言去掉 `serverError.teamFlow.*`、`server.teamJudge.*`。
- `shared/team-pipeline.ts` 只留画布用的 `FlowStage`、`PipelineStage`、`PIPELINE_STAGES`、`FlowLineWire`、`ProjectPipelineWire`；团队流水线路由的类型和 `stageLines` 删掉（删前在各分支查过没人用）。
- `phone-protocol` 的 `TeamSetupStage` 和 `TeamSetupOperation.stages` 只为判定存在，一起删。

### 应用

- 删 `src/components/team-pipeline/`、`src/state/team-pipelines*`、`src/lib/team-pipeline*`、`src/components/TeamCanvas.pipeline.dom.test.ts`。`TeamCanvas.tsx` 不再读流水线：每个团队都是负责人一列、成员一列，没有连线、环节标签和"重新判定"。`TeamMapPage.tsx` 本来就没有流水线，不改。
- 删 `scripts/testing/team-pipeline-preview.tsx`、`team-pipeline-shots.ts`、`team-pipeline-map-ui.e2e.test.ts` 和 `docs/verification/team-pipeline-map.md`；`team-canvas-ui.e2e.test.ts`、`docs/verification/README.md`、`team-setup.md` 里去掉流水线。
- 各语言去掉 `teamPipeline.*`。

### 端到端（`server/production-legacy-lines.e2e.test.ts`）

- 和 `server/production.e2e.test.ts` 一样隔离：脚本化假引擎、生成的测试 MCP、临时数据目录。共用的搭建抽到 `server/testing/production-fixture.ts`，两个测试都用。
- 团队建好后，在数据目录里写一份删掉的代码读的格式（version 2）的 `team-flows.json`，给团队画上从负责人一路到后期的连线，重启服务器，再建项目。
- 断言：从计划跑到每一集完成；负责人在群聊里用 `list_bots` 看得到每集的 bot，用 `coordinate_bots` 问得到它，而它不在群聊里；在自己的对话里也能把活交给某一集的后期；还能问主 bot，联系不到原团队的 bot；原团队里负责人联系得到连线上隔得远的成员，这个成员也联系得到负责人；负责人的提示词讲制作的做法、不讲上下游；`team-flows.json` 原样留着；`/api/team-pipelines`、`/api/team-flows` 都没有了。先在现有代码上跑，看它因为负责人联系不到每集的 bot 而失败。

## 步骤

1. 计划（本文件）。
2. 共用搭建和新的端到端，在现有代码上看它失败。
3. 联系规则和负责人的提示词：先写 `peer-roster-leads.test.ts`、改 `chief-of-staff.test.ts` 等测试，看它们失败，再改 `peer-roster.ts`、`chief-of-staff.ts`、`agents-call.ts`、`server/index.ts`，删 `server/team-flow/`。
4. 建团队不再规划环节：`team-setup-requests`、工具说明和 golden、`side-jobs`、假引擎、删 `server/team-judge/`、`ci-scope`、错误文字和各语言。
5. 应用：团队图、状态、预览、UI 测试、文档、各语言。
6. 检查：服务端和应用的类型检查、相关单元测试、两条端到端、`lint`、`i18n:check`、文件大小、`ci-scope`、`ci-workflow`、`verification-docs`；UI 测试按章程加锁，截图放 `/tmp/omb-wt-pb-lines/`。

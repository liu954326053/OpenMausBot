# 项目画布的服务器端：实现计划（第 5 块，服务器）

日期：2026-11-21 · 设计：`docs/superpowers/specs/2026-11-21-teams-flow-project-canvas-design.md` 第 5 节 · 分工：`OpenMausBot-wt/CHARTER.md`

**目标：** 每个项目有一份存在服务器上的画布文档；程序通过接口读快照、改画布、上传和读文件、带参考内容给机器人派任务，并从现有的事件推送得知变化；项目里的机器人通过工具读画布、放和改自己的节点、触发生成。不做界面。

**做法：** 新代码放在 `server/project-canvas/`，接口放在 `server/routes/project-canvas.ts`。`server/index.ts` 只加一行：建好画布的宿主，把它的接口挂进 `ROUTES`，把机器人工具的内部接口交给 `server/routes/internal-tools.ts`（照 `setTeamProjectLookup` 的做法在模块里登记）。操作的语义照 infinite-canvas 的 `applyCanvasAgentOps`，移植的文件开头保留它的 MIT 声明。

## 合同

`shared/project-canvas.ts`，第一个提交。和分工文件里写的相比，补了这些：

- 操作的完整形状（`CanvasOp`），请求和回答（`CanvasOpsRequest`、`CanvasOpsResponse`），冲突和只读时的 409 回答（`CanvasConflict`、`CanvasReadOnly`）。
- 快照（`CanvasSnapshot`）：存的文档加上机器人节点、派发线、每个机器人推出来的状态（`CanvasBotState`），以及项目的归档和文件夹状态。
- 事件 `ProjectCanvasEvent`：`{ kind: "project-canvas", projectId, revision, reason }`。
- 派任务、上传的请求和回答；和生成那块之间的两个形状：`CanvasGenerationRequest`（画布交给生成的）和 `CanvasGenerationUpdate`（生成每次变化时报回来的）。
- 生成配置节点（config）也带提示词、状态和参数，外加 `generationMode`；文本节点可带 `fontSize`，图片和视频可带原始宽高，音频和视频可带时长。这些都是 infinite-canvas 原有的字段。
- 常量：`素材`、`产出` 两个文件夹名，各类型节点的默认大小，各种长度和数量上限。

## 这一块定下的细节

### 文档

- 存在 `<数据目录>/project-canvases/<项目 id>.json`，权限 0600，用 `writeFileAtomic` 原子写入。文件里除了文档本身，还存最近 200 次修改各自动了哪些节点、连线、视口、背景（合并要用）。
- 没有文件就是空画布，版本 0；第一次修改时才写文件。
- **读不出来的文件**（不是合法 JSON，或者不符合格式）：原样留着，绝不用空文档覆盖。读快照回答 500 并说明画布文件读不出来、已原样保留；所有修改、上传、机器人工具都拒绝；日志只写一行原因。和项目清单（`registry.ts`）的做法一样。
- 每次修改版本加一。同一个项目的修改排队一个个做，不会交错。
- **旧版本上的修改**：带 `baseRevision` 时，把这次操作碰到的东西（节点 id、连线 id、视口、背景）和这个版本之后改过的比。没有交集就在当前文档上照做（合并）；有交集就整批拒绝，回答 409 和改过的那些 id。比保存的历史还旧时回答 409 `canvas_stale`，要求重新读快照。不带 `baseRevision` 就直接在当前文档上做。
- **归档的项目**：能读快照、能读文件；修改、上传、派任务、机器人改画布、触发生成都拒绝（409 `canvas_read_only`）。
- **文件夹不在的项目**：快照照常（`folderState: "missing"`），只改文档的操作照常（挪位置、改文字），因为文档不在项目文件夹里；上传、读文件、派任务、生成都拒绝并说明文件夹不在。机器人这时本来就不能跑。
- **从项目清单里移除的项目**：只有建项目失败时的撤销会移除。它的文档原样留在磁盘上，不删也不挪，接口按找不到项目回答 404。原因：清单读不出来时也列不出任何项目，按"不在清单里就删"会误删真实的画布。

### 快照

- 项目的每个机器人一个节点 `bot:<id>`。存的只是位置和大小；名字、职位、是否负责人、状态、在做什么、最新输出、等你回复的卡片都是读的时候算的。
- 机器人节点没人摆过时，位置用服务器的默认布局：派发线的树从左往右，负责人在最左，每个机器人右边留一条放它的节点的通道，每棵子树占自己的一段高度，高度算上它已经放的节点。快照里 `placed: false`。程序可以用自己的布局替换，只要把位置存回来（`update_node`）。这样机器人放节点用的位置和用户看到的一致。
- 派发线：`parentOf(botId)` 由流程那块提供；集成前的默认是负责人是其他所有机器人的上级。线的 id 是 `dispatch:<上级>:<下级>`，不存，操作里不能改。
- 机器人加入项目就出现；离开就消失，它放的节点留着。两头不都在画布上的内容线不出现在快照里，但仍然存着。
- **状态**：等你回复（它有没答的提问或审批卡片，或者任务的活动状态是 waiting-on-you）> 工作中（有对话在跑）> 排队中（有消息在排队等它）> 出错（它最近一次活动的对话最后一条是失败的那一行）> 空闲。
- **在做什么**：工作中时，取正在跑的对话里最新一条活动行（工具行）的文字，就是聊天里活动摘要显示的那句。
- **最新输出**：它所有对话里最新的一条机器人文字回复。只看查看者能打开的对话；经过 `redactSecretsInText`，最多 2000 字，超出时截断并标出。附带消息 id、对话 id、时间。为了读得快，服务器在内存里按对话记下最新的回复，靠 `store.onChange` 更新，第一次用到时读对话末尾的一段。
- **等你回复的卡片**：只来自查看者能打开的对话；卡片内容整体经过密钥遮盖。
- 可见性：用对话那边同一套规则（`visibleTo(viewerFor(auth)).thread(threadId)`）。画布接口在项目接口后面，本来就只有所有者和管理员能进；Team Cloud 的管理员也看不到别人的私人对话，所以这一层过滤仍然要做。

### 接口

都在 `/api/team-projects/:id/canvas` 下，项目接口已有的"只有所有者和管理员"在前面拦着，自己再检查一次。

- `GET …/canvas`：快照。
- `POST …/canvas/ops`：`{ baseRevision?, ops }`，回答新版本和新加的节点、连线 id。人能改所有内容节点；机器人节点只能挪位置、改大小；不能加或删机器人节点，不能动派发线。
- `POST …/canvas/files?name=&x=&y=`：原始字节，`content-type` 是类型。存进项目文件夹的 `素材/`，重名时加序号；按类型加一个节点（没给位置就放在画布右边）。上限用现有的 `FILE_MAX_BYTES`，支持 `uploadId` 重试。
- `GET …/canvas/files?path=`：按相对路径读文件，支持 Range（视频要用）。
- `POST …/canvas/tasks`：`{ botId, text, threadId? }`，把连进这个机器人节点的参考内容带上，发到它在本项目里的对话（默认它当前打开的那个），走现有的发消息那条路（`acceptDirectSend`），所以排队、Stop、审批这些规则不变。

**路径安全**（读写文件都用同一个函数）：只收相对路径；拒绝空路径、绝对路径、`..`、反斜杠和控制字符；第一段不能是 `.magic-team`（大小写都算）；实际路径（`realpath`，跟随所有链接）必须在项目文件夹的实际路径里面，且不能落进 `.magic-team`；读的必须是普通文件。写的时候父目录用 `realpath` 检查，文件用不跟随链接的方式新建（`wx`），不覆盖已有文件。

**参考内容怎么带**：文本节点带标题和正文；分镜带标题、提示词和各项参数；图片复制一份进附件目录，作为图片附件（`<attached-image>`），模型能直接看到；视频、音频、文件用 `<attached-file>` 指向项目文件夹里的实际路径，机器人在项目文件夹里本来就能读。消息正文先写任务，再写"画布上连进来的参考内容"一段。

### 事件

- 文档改了：广播 `{ kind: "project-canvas", projectId, revision, reason: "document" }`。
- 推出来的东西变了（项目里机器人的状态、新回复、成员增减）：同样的事件，`reason: "bots"`，每个项目 500 毫秒内合并成一次。
- 只发给管理员的连接（`adminOnly`），事件里只有 id 和版本，不带内容；程序收到后重新读快照，快照按查看者过滤。

### 机器人的工具

三个工具，只给项目里的机器人，主机器人没有（主机器人不属于任何项目，`teamProject` 为空）。

- `project_canvas_read`：不带参数时是整张画布的摘要（每个节点一行：id、类型、标题、谁放的、位置，文字截到 120 字；再列连线）；带 `nodeId` 是这个节点的全部内容；`around: "me"` 是连进和连出自己节点的那些节点的全部内容。
- `project_canvas_apply`：一批操作。机器人只能加文本和分镜节点；只能改和删自己放的节点；连线时至少一头是自己放的节点或自己的机器人节点，断线只能断这样的线；不能改视口和背景。被拒绝时说明是哪个节点、为什么。
- `project_canvas_generate`：让一个图片、视频或分镜节点开始生成，走依赖 `startGeneration(...)`。集成前的默认实现回答"还没设置"。机器人触发时图片一次最多 4 张，超过就拒绝，请它让用户在画布上点生成。
- 机器人加的节点没给位置时：放在它的机器人节点右边，通道里它已经放的节点下面，并从它的节点连一条内容线过来。放节点不需要用户确认。
- 机器人的回复不用工具，快照自己会显示在它的节点上。
- 接线照现有的项目工具：`OMB_PROJECT_CANVAS` 环境变量按会话决定是否给工具，加到 `AGENTS_MCP_ENV` 和 `BOX_ENV_OMB_NAMES`；内部接口在 `/api/internal/project-canvas/*`，经过内部接口那一段所有的检查（能力、外部内容的围栏、Bot API、只读草稿），这三个围栏都是白名单，所以由外部内容驱动的轮次、Bot API 对话、只读草稿的例行任务都用不了画布工具。

### 机器人交出的文件

- 监听 `store.onChange` 的新消息：项目机器人的 `attach_file` 那一行（带 `sentInTurn`、只有一个附件）。
- 原文件在项目文件夹里：节点直接指向它的相对路径。在别处：把附件的副本复制进 `产出/`，节点指向复制的文件。
- 同一个文件不出第二个节点：同一个机器人已经有指向同一相对路径的节点就跳过；复制到 `产出/` 的按内容比较，内容一样的已经有了就跳过。
- 节点放在机器人节点右边、往下排，并连上线。

### 生成

- 生成那块负责真正的生成。这边提供：`startGeneration` 依赖（默认拒绝），以及 `generationChanged(update)` 给它的回调用：更新节点的状态、任务编号、失败原因；成功时空的图片或视频节点填进第一个结果，其余的、以及分镜和已有文件的节点的结果，变成右边的新节点，连上线，排在之前生成的下面。
- 项目的生成配置由生成那块存，不放在画布文档里。

## 文件

- `shared/project-canvas.ts`：合同。
- `server/project-canvas/paths.ts`：项目文件夹里的路径安全、唯一文件名。
- `server/project-canvas/ops.ts`：操作的校验和执行（移植），归属规则。
- `server/project-canvas/document-store.ts`：读写、版本、历史、合并、读不出来时的处理、按项目排队。
- `server/project-canvas/placement.ts`：默认布局和机器人节点的放置。
- `server/project-canvas/snapshot.ts`：机器人状态、输出、卡片、派发线、可见性过滤。
- `server/project-canvas/references.ts`：派任务时的参考内容。
- `server/project-canvas/handover.ts`：`attach_file` 变节点。
- `server/project-canvas/agent-tools.ts`：工具定义和调用。
- `server/project-canvas/host.ts`：把以上接起来，事件，依赖的默认实现。
- `server/routes/project-canvas.ts`：程序用的接口和机器人用的内部接口。
- 接线：`server/index.ts` 一行；`server/routes/internal-tools.ts` 一项；`server/drivers/agents-catalog.ts`、`agents-call.ts`、`agents-mcp-env.ts`、`server/agents-turn.ts`、`server/bot-box/env.ts`、`server/agent-tool-policy.ts` 各加对应的一处。

## 测试

单元测试：操作（每种操作、上限、校验）、版本和合并（合并、拒绝和改过的 id、太旧）、归属（机器人只能改自己的，机器人节点只能挪）、放置（右边、往下、给了位置就用给的）、路径安全（`..`、绝对路径、出去的链接、`.magic-team`）、读不出来的文件不被覆盖、快照的状态和过滤、参考内容、交出的文件去重。

端到端（真服务器加假引擎，证据放在 `/tmp/omb-wt-canvas-server/`）：从团队建项目后的快照（机器人、默认派发线、状态）；机器人回复出现在节点上、密钥被遮盖；机器人用工具加分镜节点（位置和连线），改别人的节点被拒绝；`attach_file` 出一个节点、同一文件不出第二个；上传进 `素材`、出项目文件夹的路径被拒绝；从画布派的任务带着参考内容到达；旧版本上的修改按规则合并或拒绝；看不到某个对话的查看者拿不到它的文字；改动时有事件。

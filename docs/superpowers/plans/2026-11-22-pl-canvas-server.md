# 流水线画布的服务器端：实现计划（pl-canvas-server 轨道）

日期：2026-11-22 · 设计：`docs/superpowers/specs/2026-11-22-drama-pipeline-and-jianying-design.md` 第 5 节 · 分工：`OpenMausBot-wt/PIPELINE-CHARTER.md`

**目标：** 画布上机器人之间的线和环节来自流水线；产物节点由程序按"谁做的、是什么"来连；每个镜头有一个视频创作节点，生成的视频是它后面的候选，每个镜头最多一个选用；角色是一个组；旧画布读到时补齐。给接力、剪映两条轨道留好读镜头、选用、放成片、标记过期、标记剧本和订阅事件的出口。不改 `src/` 下的界面。

**做法：** 规则都写成纯函数，放在 `server/project-canvas/` 的新文件里；`service.ts`、`ops.ts` 只加挂钩。

## 文件

| 文件 | 内容 |
|---|---|
| `flow.ts`（新） | 从 `projectPipeline` 得到项目里每个机器人的环节和流程线；不在流水线里的机器人记为"其他"，挂在负责人下面 |
| `placement.ts` | 没人摆过的机器人按环节分列：负责人、编剧、角色设计、分镜、后期，从左到右；"其他"在负责人下面单独一列；每列右边按环节留出产物的位置 |
| `snapshot.ts` | `stages` 和 `dispatch` 线来自流水线，一个机器人可以有多条进线 |
| `pipeline-links.ts`（新） | 程序该连的线（表见下），以及"这次变化前后各该有哪些线"的差：新该有的补上（已有同向的线就标成 `pipeline`），不该再有的拿掉。人删掉的线只要规则没变就不再补回来 |
| `pipeline-shots.ts`（新） | 镜头的视频创作节点、候选视频、选用、过期标记、从镜头生成时改走创作节点 |
| `pipeline-groups.ts`（新） | 角色组：角色文字节点一出现就建组；从它（或组里的图）连出去的图片进组，排在它右边，组框跟着长大 |
| `pipeline-upgrade.ts`（新） | 旧画布补齐：每个镜头补创作节点，镜头后面的视频变成候选并挪到创作节点右边，最新的那个选用 |
| `pipeline.ts`（新） | 每次修改之后跑一遍上面几步，并算出要通知的事件 |
| `pipeline-api.ts`（新） | 给别的轨道的出口：`shots`、`selectTake`、`addFinal`、`markStale`、`markScript`、`on` |
| `document-store.ts` | 连线保留 `pipeline`；文件里多记一项"这些线是按哪份环节连的"（没有这一项就是旧画布）；最近删掉的节点多记它的角色，人撤销删除时还原 |
| `ops.ts` | `role`、`shotId`、`selected`、`stale` 只由程序写：人加节点时带着的丢掉（撤销删除时按记录还原），改节点时带着的拒绝；只有角色设计环节的机器人能给自己新加的文本节点写 `role: "character"`；机器人不能删 `pipeline` 线 |
| `service.ts` | 读和改之前先补齐；改完跑 `pipeline.ts`；生成镜头时走它的创作节点；生成成功的视频落成候选并选用 |
| `routes/project-canvas.ts` | `POST …/canvas/select-take` |
| `agent-tools.ts`、`drivers/agents-project-canvas-tools.ts` | 状态里带环节和 `pipeline`；工具说明改写 |

## 程序连的线

| 节点 | 线 |
|---|---|
| 剧本（`role: script`） | 每个编剧 → 它；它 → 每个角色设计、每个分镜（写它的编剧自己除外） |
| 角色（`role: character`） | 放它的机器人 → 它；它 → 每个分镜（放它的机器人自己除外） |
| 镜头 | 放它的机器人 → 它；它 → 它的创作节点；连进镜头的图片 → 创作节点 |
| 候选视频（`role: take`） | 创作节点 → 它；选用的那个（镜头还在时）→ 每个后期 |
| 成片（`role: final`） | 每个后期 → 它 |

## 顺序

1. 合同补充和文档存储（`pipeline` 线、环节记号、删除记录里的角色）。
2. 流程线、环节、默认分列。
3. `ops.ts` 的规则。
4. 程序连线和差。
5. 创作节点、候选、选用、过期、生成改道。
6. 角色组。
7. 旧画布补齐。
8. 出口、`select-take` 接口、事件。
9. 机器人工具的说明和状态。
10. 端到端测试跟着改，跑分工文件里的检查。

每一步先写测试，看它因为正确的原因失败，再写代码，一步一个提交。

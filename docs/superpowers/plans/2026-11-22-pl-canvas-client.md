# 画布上的流水线（pl-canvas-client 轨道）

日期：2026-11-22 · 设计：`docs/superpowers/specs/2026-11-22-drama-pipeline-and-jianying-design.md` 第 5、6 节的界面部分 · 章程：`OpenMausBot-wt/PIPELINE-CHARTER.md`

**目标：** 项目画布按流水线画：机器人按环节排成列，镜头一行三个节点，视频上能看出和换掉“选用”，上游改了的节点有标记，运行的进度和批量生成前的确认在画布顶栏下面，后期机器人的面板里有剪映草稿这一块。数据仍然只经过 `CanvasBackend`；服务器那边由别的轨道同时在做，所以先对内存实现开发和测试，服务器实现照章程列的路由写。

## 做法

1. **排列**（`src/lib/project-canvas/stage-layout.ts`，取代 `tree-layout.ts`）
   - 列按环节从左到右：负责人、编剧、角色设计、分镜、后期；一个机器人有几个环节时站在第一个环节的列里；没人的环节不占列；“其他”的机器人排在负责人下面，和负责人同一列。同一列的机器人从上到下。负责人留在原地，其余按它算。
   - 每个机器人做出来的节点在它右边、下一列的左边，一个节点一行。归谁：它建的节点，或者服务器从它连过去的流水线线（`pipeline: true`）指着的节点；它建的组（或装着它的角色设定的组）连同里面的节点整块挪。
   - 镜头从上到下，一行三格：镜头、它的视频创作节点（`role: "creation"`，`shotId` 相同）、它的视频（`role: "take"`），后生成的视频排在先生成的下面。没有这些标记的旧画布照旧：只由它的节点喂出来的图片、视频排在右边一格。
   - 不是机器人做的镜头留在原地，它的视频创作和视频排到它右边。
   - 机器人之间的线不再决定位置，所以一个机器人可以有几条线进来。线画的时候：目标不在右边（“其他”在负责人下面）走左侧的弧；中间隔着别的机器人（编剧直接连分镜）从上面绕过去。
2. **`CanvasBackend` 加的**（内存实现和服务器实现都做）
   - `selectTake`：`POST …/canvas/select-take { nodeId }`。
   - `answerVideos`：`POST …/pipeline/videos { action }`，现在服务器上还没有人答。
   - `openDraft`：`POST …/draft/open`，回 `opened: "draft" | "app"`。
   - `setFinalFilm`：`POST …/final { path }`；`localPathOf?(file)`：桌面应用里一个选中的文件在这台电脑上的路径（`window.ogb.getPathForFile`），网页和操控另一台电脑时没有这一项，界面就不出“选择成片”。
   - 草稿本身在快照里（`snapshot.draft`），不另外读。调时间线顺序的界面这一版没有，所以不加。
   - 内存实现扮演服务器：视频创作节点生成出来的是这个镜头的视频，并成为选用的那个；选用时把这个镜头别的视频的标记去掉，连到后期的那条线跟着换；确认、重试、跳过只改运行的状态；选成片时在后期机器人右边加一个成片节点。
3. **节点**
   - 节点上方那一行：左边是“它是什么”的小标签（机器人的环节；剧本、角色设定、角色、视频创作、成片），一直显示，后面是悬停才出现的标题；右边是“上游有更新”和视频的“已选用”或“选用”按钮。
   - 镜头的面板只剩参考和提示词，不再有模型、设置和“生成视频”。镜头节点里只显示提示词和参考数。
   - 视频创作节点的面板是生成配置的面板去掉“生成什么”的切换和提示词：参考、模型、分辨率、比例、时长、“生成”。提示词是它那个镜头的；镜头没有提示词时按钮不能点并说明原因。节点里显示镜头的提示词、时长、分辨率、模型。
   - 带 `pipeline: true` 的线和别的内容线画法、删除都一样，不用改。
4. **运行**（`PipelineRunBar`，画布顶栏下面的一行，有 `snapshot.run` 才出现）
   - 每个环节一个小标签和状态（等待、进行中、完成、出错），“视频”排在后期之前，生成中显示“已完成/总数”。
   - `videos.status === "confirm"`：写明有几个镜头，一个主按钮“生成 N 段视频”（N 是还没有视频的镜头数）。`failed`：写明几个镜头没有视频，“重试失败的镜头”和“跳过，继续”。请求失败时在旁边写原因，按钮留着。归档的项目按钮不能点。
5. **后期机器人的面板**（`DraftSection`，有 `snapshot.draft` 且机器人的环节里有后期才出现）
   - `unavailable`：没装剪映（“编辑”不能点，说明要先装）、剪映的版本认不出、应用在操控另一台电脑（只有一句说明）。`none`：等所有镜头有视频后生成。`written`、`kept`：草稿的名字和“编辑”；`kept` 多一句“剪映保存过的那份没有动”。点“编辑”后回的是 `app` 时写明去剪映里打开哪一份。
   - 下面是导出成片的文件夹和复制按钮；应用拿得到文件路径时有“选择成片”，选的文件不在项目文件夹里就用一句话拒绝，不发请求。项目文件夹取导出文件夹的上一级（`产出` 在项目文件夹里）。
6. **文字**都在 `projectCanvas.` 下，英文、简体、繁体、巴西葡萄牙语各加在一处。
7. **样例和截图**：`src/testing/project-canvas-sample.ts` 加一个漫剧项目（五人流水线、剧本、两个角色组、八个镜头各带视频创作和一到三段视频、运行、草稿），原来的样例把镜头补成三个节点。预览页用 `?sample=drama&lang=zh&run=…&draft=…&open=…` 切换。中文浅色、深色截图放 `/tmp/omb-wt-pl-canvas-client/`，占用界面夹具时按章程加锁。

## 不碰的

`server/`、团队地图、`shared/` 里的契约（有错才改，并在报告里说明）。

## 顺序

排列 → 后端接口和两个实现 → 节点和面板 → 运行条 → 草稿 → 样例、预览和截图 → 检查。每一步先写测试，看它因为该有的原因失败，再写代码，然后提交。

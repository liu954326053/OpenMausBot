# 项目（服务端）：实现计划（第 3 块）

日期：2026-11-20 · 设计：`docs/superpowers/specs/2026-11-20-projects-templates-skills-design.md` 第 4 节 · 状态：已完成

**目标：** 用户在设置里选好项目根目录后，可以用一个团队模板建项目：根目录下多一个项目文件夹，程序里多一个同名部门和一支按模板配好的团队。项目可以归档和恢复。

**做法：** 项目清单和根目录存在 `<数据目录>/projects.json`。建团队用现有的导入代码（`server/package-import.ts`），模板内容通过模板库的接口读。所有逻辑放在 `server/team-projects/` 下，`server/index.ts` 只接线。

不在这一块里：机器人自己的文件放进 `.magic-team/bots/<角色>/`、缺失或归档项目的机器人不接活（`workspaces`）；项目之间互相看不见（`isolation`）；页面（`projects-ui`）；主 bot 的工具（`lead-bot`）；模板库本身（`templates`）；按模板更新和存回模板（`template-sync`）。

## 这一块定下的细节

1. **`projects.json`** 是 `{ version: 1, root?, projects: [...] }`。只有本程序写它，每次整份原子写入（`server/atomic.ts`），权限 0600。写之前先按读取时的规则检查一遍，下次启动读不回来的内容不会写进去。
2. **读不出来不等于没有。** 文件不存在算空清单。文件在但读不出来或内容不对：清单进入“读不出来”状态，列表接口报错，所有修改都拒绝，原文件一个字节也不动。修好文件后不用重启，下一次请求会重读。这期间项目的部门照样受保护（见第 11 条），靠的是机器人自己身上的项目标记。
3. **项目根目录**必须是绝对路径、已存在、是文件夹、可写，并且不在程序数据目录里面（给出的路径和它实际指向的位置都检查）。换根目录不移动已有项目，每个项目自己记着完整路径。建项目时再检查一次根目录是不是在数据目录里（手改过 `projects.json`、或数据目录挪过位置时可能出现），在里面就拒绝，什么都不建。
4. **项目名**：去掉首尾空格后 1 到 60 个字符（部门名的上限）；不含 `/ \ : * ? " < > |` 和控制字符；不以点开头，不以点或空格结尾；不是 Windows 保留名（`CON`、`NUL`、`COM1` 等，带扩展名也算）。和已有项目（包括已归档的）或部门重名时拒绝，不分大小写。规则写成一个函数放在 `shared/team-projects.ts`，页面可以直接用。
5. **建项目**严格按设计里的 8 步，顺序是：查根目录 → 查名字 → 查重名 → 查文件夹 → 读模板 → 建文件夹和 `.magic-team` → 用导入代码建团队 → 定负责人 → 按模板设名字、模型、MCP、技能库技能，打开模板自带的技能 → 记进清单 → 写副本。从建文件夹开始，任何一步出错都按相反顺序撤销：清单记录、例行任务、群聊、机器人、导入时加的 MCP 服务、部门、文件夹。撤销只删这次自己建的东西；文件夹里要是这时已经有了别的文件，文件夹留下，并明说没清干净。同一个名字的两个请求同时到达时只建一个，另一个得到“名字已被占用”（有测试守住）。
6. **机器人的 `teamProject` 在它的文件第一次写入之前设好。** 导入代码先建机器人，再写它的技能和初始记忆。建项目期间监听机器人变化，机器人一带上模板角色标识（`installedPackage.agentKey`）就设 `teamProject` 和工作文件夹，并马上让 `workspaces` 把它自己的文件放进 `.magic-team/bots/<角色>/`。放不进去时整个建项目撤销。有测试守住这个顺序。
7. **角色名**就是模板里的角色标识。它要当文件夹名，模板里的标识不能当文件夹名或重复时，另生成一个。
8. **归档**：先暂停这个项目的例行任务（负责的机器人属于这个项目的那些，只暂停当时开着的），把暂停了哪些记在清单记录里，再写上归档时间。**恢复**只重新打开记下的那些；期间被删掉的、用户自己又打开的不动。任何一步出错就退回原样。文件夹和里面的东西不动。
9. **`.magic-team` 里的副本**，程序只写不读：
   - `project.json`：清单里这个项目的记录。
   - `team/team.json`：部门名、负责人、每个机器人的角色、名字、职责，以及模型、技能库技能、MCP 服务的**名字**。
   - `team/context.md`：部门的背景说明。
   - `team/memory.md`：已采纳的团队记忆。
   - `team/personas/<角色>.md`：每个机器人的人设；机器人删掉后对应的文件也删掉。

   更新时机：建项目时、归档和恢复时、模板版本改写时、机器人或部门有变化时（去抖 1 秒）、背景说明或团队记忆的文件有变化时（每 2 秒看一次文件的修改时间）、程序启动时。内容没变就不写。项目文件夹不在时不写，也不新建文件夹。`.magic-team`、`team` 或 `team/personas` 被换成链接时不写。同一个 `.magic-team` 里的 `bots/` 归 `workspaces` 管，这里不碰。
10. **之后加进项目部门的机器人**（负责人加的或用户加的）自动属于这个项目：设 `teamProject`，角色名是 `member-` 加 8 位十六进制（由机器人的 id 算出，项目里不重复）；它自己的文件马上放进项目文件夹（放不进去只记日志，机器人仍属于项目）。
11. **已有的机器人不能移进或移出项目的部门，项目的部门不能改名或删除。** 用户的操作在请求进来时拒绝，负责人的团队调整在执行时拒绝，都给出一句话。清单读不出来期间同样拒绝。
12. **负责人**：项目部门换了负责人，清单里的负责人跟着变。负责人被删掉而且还没有新负责人时，保留原值。
13. **工作文件夹**：项目机器人没有自己指定工作文件夹时就用项目文件夹（被清空后也回到项目文件夹，用户另选的保留）。只由同一个项目的机器人组成、自己没有指定文件夹的群聊和私聊，也在项目文件夹里干活。
14. **项目现在对应的模板版本**由模板同步改写：`setTemplate(项目 id, { id, name, version })`，写进清单和 `project.json` 副本。
15. **按模板的一个角色配置一个机器人**（职责、人设、外观、模型、MCP、技能库技能、打开模板自带技能）是一个导出的函数 `applyTemplateRole`，建项目和“按模板更新”共用。

## 约束

- `server/index.ts` 最多加 6 行（实际加 2 行，改 1 行）；`server/store.ts`、`server/config.ts`、`server/routines.ts` 一行都不加（`scripts/testing/file-size-ratchet.test.ts`）。
- 别人的代码通过约定好的接口调用（`TemplateLibraryApi`、`TeamProjectLookup`、`ensureWorkspace`、`teamProjectFolderReady`），测试里用假的。
- 接口路径和状态码按约定，不新增实时推送的消息。
- 给用户看的拒绝理由都是 `serverError.teamProject.*`，放在 `serverError.skillUpload.noSkill` 之后，有英文、简体、繁体、葡萄牙语。
- 验证用独立的测试实例，不动用户正在用的数据。

## 接口

```ts
// server/team-projects/host.ts
createTeamProjectsHost(deps): {
  api: TeamProjectsApi & TeamProjectTemplateSetter;  // list / create / archive / restore / setTemplate
  root(): string | null;           // 项目根目录，给主 bot 的建项目卡片
  lookup: TeamProjectLookup;       // 给 workspaces 的 setTeamProjectLookup
  routes: RouteHandler;
  checkSetupChange(before, fields): void;  // 负责人的团队调整，移动时抛出
}
```

HTTP：`GET /api/team-projects`、`POST /api/team-projects`、`POST /api/team-projects/:id/archive`、`POST /api/team-projects/:id/restore`、`PUT /api/team-projects/root`，状态码按约定。只有机主或管理员能用（其他人 403）。清单读不出来时一律 500 加一句话。

## 和别的部分怎么接

- `server/index.ts` 里一行建好 `teamProjects`，同一行把 `teamProjects.lookup` 交给 `workspaces`（`setTeamProjectLookup`），并挂上路由。
- `teamProjects.api.create` 和 `teamProjects.root` 给主 bot 的建项目卡片（`lead-bot`）。
- `teamProjects.api.setTemplate` 给模板同步（`template-sync`）。
- 负责人的团队调整在执行前调用 `teamProjects.checkSetupChange`。
- 项目文件夹在不在，用 `workspaces` 的 `teamProjectFolderReady`。

## 需要用户确认的决定

1. **项目根目录存在 `projects.json` 里，不进 `config.json`。** 选它是因为 `server/config.ts` 已经到行数上限，而且这个程序里各功能的设置本来就各存各的文件；清单和根目录在一个文件里，一次写入。以后要挪：很容易，只动一个字段。
2. **归档时暂停了哪些例行任务，记在清单的项目记录里**（`pausedRoutineIds`），不出现在接口和 `project.json` 副本里。以后要改：容易。
3. **一个项目的例行任务，指负责它的机器人属于这个项目的那些。** 以后要改：容易。
4. **项目名规则**见上面第 4 条，上限 60 个字符是因为部门名最多 60。以后要放宽：容易，但已有的名字不受影响。
5. **项目的部门不能改名、不能删除；已有机器人不能移进移出。** 选“拒绝”而不是“跟着改”，是为了让项目名、文件夹名、部门名一直一致。以后要支持改名：中等，需要同时改清单、部门，还要决定文件夹改不改。
6. **项目里的机器人一律用模板里的名字。** 两个项目里可以都有“编剧”；项目外已经有同名机器人时也不加编号（程序本来就能分辨同名机器人：名单里带着部门，发消息遇到重名会要求指明是哪一个）。同一个模板里两个角色同名时，在项目内加编号区分。现有的导入功能会给重名的加编号，这里特意改回来。以后要改：几行。
7. **模板自带的技能，建项目时直接打开。** 现有的“从文件导入”是先停用、等用户检查；这里认为模板是用户放进自己模板库的，选模板建项目就是确认。以后要改成先停用：一行。
8. **模板里写的模型在这台电脑上没有时，照样写给机器人**，由用户之后在机器人设置里换；不拒绝建项目，也不悄悄换成默认模型。以后要改：小。
9. **项目文件夹“在不在”，看它是不是一个绝对路径上的文件夹**（和 `workspaces` 用同一个判断）。不在时列表里标成“缺失”，程序不会重新创建它。
10. **项目的接口只有机主或管理员能用**（列表、建项目、归档、恢复、选根目录）。其他成员和受限的配对设备读不到项目列表，在他们那里项目只显示成普通部门。理由：列表里有每个项目的文件夹路径。以后要开放只读列表：几行，但要先决定路径给不给看。
11. **建项目中途程序被强行关掉**（不是出错）时不会自动清理，可能留下一个普通部门和一个文件夹，可以手动删。出错的情况都会撤销干净。
12. **之后加进项目的机器人，角色名是 `member-` 加 8 位十六进制，不用名字生成。** 模板的角色标识是按名字或序号生成的；后加的机器人如果也这样生成，以后模板新增的角色可能正好是同一个标识，“按模板更新”时两个不相干的机器人会被当成同一个角色（这是 `templates` 提出的风险）。代价：`.magic-team/bots/` 里这类机器人的文件夹名看不出是谁，要到 `team/team.json` 里查名字。以后要改：一个函数。
13. **项目机器人的工作文件夹默认是项目文件夹**：没有指定时自动补上，清空后也回到项目文件夹，用户另选的保留。只由同一个项目的机器人组成、自己没有指定文件夹的群聊和私聊也一样。以后要改：几行。
14. **`projects.json` 损坏期间**：项目的部门照样不许移进移出、改名、删除；项目的机器人暂时不接活（`workspaces` 的规则）；在项目部门里新建的机器人仍然算进项目，清单恢复后补上工作文件夹。选它而不是“全部放开”，是为了不让项目在这段时间混在一起。以后要改：小。
15. **机器人自己的文件在它加入项目的那一刻就放进项目文件夹。** 建项目时放不进去（比如文件夹不可写），整个建项目撤销；之后加的机器人放不进去只记一条日志，机器人仍属于项目，下次用到时再放。以后要改：小。
16. **清单里的“模板”一栏记的是项目的团队现在对应哪个模板的哪个版本**：建项目时是所用的模板，“按模板更新”或“存回模板”后由模板同步改写。没有另外保留“最初用的模板”。以后要保留：加一个字段。
17. **建项目失败时给用户的那句话里带着系统原始的出错信息**（可能有本机路径），同时写进日志。只有机主和管理员看得到。以后要改成只进日志：一行。
18. **只差大小写的部门名，程序一向当成两个部门**；所以在“stand-in bride”里新建的机器人不会进“Stand-in bride”项目。项目名查重则不分大小写，建不出只差大小写的两个项目。以后要统一：要改部门本身的规则，不在这一块。

## 已知的缺口

- 这个分支单独运行时，`GET /api/bots` 里还带着机器人的 `teamProject`；`lab/integration` 上已经去掉（约定里它不上线）。
- `projects.json` 损坏时，项目机器人拒绝接活的那句话（`workspaces` 的）建议“重启”，但重启修不好文件；日志里有文件位置。
- 删掉项目负责人后，清单里的负责人仍指向已删除的机器人，直到部门有了新负责人。
- 这个分支单独运行时，别的机器人的群聊可以被归到项目的部门下面（它不会因此用上项目文件夹）；`isolation` 的部分规定归到项目部门的群聊只能有这个项目的机器人，`lab/integration` 上已经有。
- 项目可以取名“General”，侧边栏里会和默认分组的显示名一样。
- 这一版没有删除项目。
- 项目文件夹改名或挪走后，没有“重新指向新位置”的入口：把文件夹放回原处就恢复，否则只能手改 `projects.json`。
- 备份和“搬到云端”我没有验证。按代码看，它们处理的是程序数据目录；`projects.json` 在数据目录里，项目文件夹（连同项目机器人的记忆和自学的技能）在数据目录外。在另一台电脑上恢复后，项目会显示“找不到项目文件夹”，机器人不接活。
- 清单读不出来期间加进项目部门的机器人，要等它下一次有变化或程序下次启动，才补上项目文件夹作为工作文件夹；在那之前它没有工作文件夹。
- 桌面版上，机器人的命令行和程序在同一台电脑，仍能直接读 `GET /api/team-projects`（和 `GET /api/bots` 是同一个现状）。

# 效果图 vs 实现：可重复对照工具（vis-audit 轨道）

日期：2026-11-24 · 章程：`OpenMausBot-wt/BOARD-CHARTER.md` · 设计：`docs/superpowers/specs/2026-11-24-production-board-design.md`

**目标：** 一条命令把老板的效果图 `docs/无限画布效果图/index-v5/` 和 MagicBot 的制作看板放在同一视口下逐元素对照，产出机器可读的 `parity.json`、按差距排序的 `report.md` 和左右拼图。改造完成后改代码、重跑，差距应当变小。只加 `scripts/` 工具和 `docs/` 说明。

## 做法

1. **映射表**：`scripts/testing/board-visual-map.json`，一行一个元素：id、中文名、分组（chrome / cards / panels）、效果图选择器、我方选择器、效果图代表节点、我方先聚焦的阶段。首版 15 个：阶段条、工具栏、小地图、10 种卡片、对话窗、详情弹窗。
2. **两个页面，同一套采集**：
   - 效果图用仓库里的 `node:http` 静态服务挂在 8781（`file://` 被拒）。
   - 实现用 `launchVerificationServer`（`control-omb launch` 背后的同一个函数）起隔离夹具：临时数据目录与 HOME、自选端口、假引擎；再用 `mountPreview` 把看板预览 `project-canvas-preview.tsx` 挂在 8790 起，`/api` 代理到夹具。看板本身用仓库自己的内存样例（与 `board-cards-shots.ts`、`project-canvas-ui.e2e.test.ts` 同源），不读用户数据。
   - 截图与求值复用 `scripts/testing/headless-chrome.ts`（`verify-*.ts` 用的同一个无头 Chrome），不另造一套。
3. **每个元素采集**：`getBoundingClientRect`、`getComputedStyle` 的宽高、四角圆角、背景、边框（宽/样式/色）、阴影、字号、行高、四边内边距；颜色在页面里经 canvas 归一成 RGBA；记录看板缩放，便于解释屏幕尺寸。
4. **差异评分**：每个属性归一成 0–1，按权重（尺寸 0.20、背景 0.16、边框 0.17、内边距 0.15、阴影 0.10、字号行高 0.14、圆角 0.08）加权，乘 100 作为「差距分」；按分降序写报告。
5. **输出** `/tmp/omb-vis-audit/`：`mockup/`、`app/`、`side-by-side/`（浏览器里用 data URL 拼，等高对齐）、`parity.json`、`report.md`。另出「打开时」与「全局」两组整板对照。
6. **入口**：`pnpm vis:audit`；`--viewport 1440x900`、`--only cards,chrome,panels`、`--app-url`（审计已在跑的隔离夹具看板）、`--skin midnight`、`--lang zh`。
7. **测试先写**：`scripts/testing/board-visual-audit.test.ts` 覆盖参数解析、映射表完整性、数值/颜色解析、评分单调性、排序、报告含截图路径、拼图 HTML。

## 不碰的

`src/**`、`shared/**`、`server/**`、语言文件、`source-hashes.json`、`~/.magicbot`、`~/Library/Application Support/MagicBot`、剪映目录。

## 顺序

计划 → 映射表和测试（红）→ 实现 → 拿锁跑一次真实对照 → 写报告 → 检查（测试、类型、lint、锁释放）。

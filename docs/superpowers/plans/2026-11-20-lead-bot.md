# 主 bot 建项目：实现计划（第 4 块）

日期：2026-11-20 · 设计：`docs/superpowers/specs/2026-11-20-projects-templates-skills-design.md` 第 5 节

**目标：** 用户跟全局主 bot 说想做什么，主 bot 挑一个合适的团队模板、提议建项目；对话里出现确认卡片，用户点“创建”后项目建好，需求交给项目负责人，卡片上有进入项目的入口。

**做法：** 不发明新机制，照搬现有的“先提议、用户确认、再执行”这条路（MCP 服务器卡片 `server/host/mcp-requests.ts` 和团队设置卡片 `server/team-setup-requests.ts`）：工具 → 内部接口 → 卡片存在对话里 → 用户在卡片上回答 → 执行 → 把结果告诉停在卡片上等待的主 bot，它接着干。模板库和建项目由别的模块提供，这一块只通过约定好的接口调用。

## 这一块定下的细节

1. **谁是全局主 bot。** 现有的 MagicBot 助手（`defaultBot`，并且有负责人权限，即 `holdsMagicBotTools`），而且不属于任何项目（没有 `teamProject`）。只有它的工具列表里有这两个工具；内部接口对其他机器人一律拒绝，不管它们怎么调用。
2. **两个工具。**
   - `list_team_templates`：列出每个团队模板的编号、名称、适合的题材、各个角色（标出负责人）。
   - `propose_team_project`：项目名、团队模板编号、用户的需求。
   - 工具说明里写明：没有合适的模板就照实说并列出现有模板；主 bot 不能新建或修改模板；提议后结束这一轮，等用户决定。
3. **只在主 bot 自己的对话里用**，群聊里不提供。
4. **提议时先查一遍**，查不过就不出卡片，直接告诉主 bot 原因：还没指定新项目放在哪个文件夹；模板编号不存在（同时列出现有模板）；项目名不是一个单独的文件夹名；需求是空的或太长。项目名是否重名由“建项目”那一步判断。
5. **卡片内容。** 项目名、将要建的文件夹路径、团队模板名、成员（负责人在前并标出）。两个按钮：“创建”和“取消”，在输入框上方的回答栏里，和其他确认卡片一样。卡片上不显示需求原文。
6. **一定出卡片。** 不管机器人的权限等级多高，都不会跳过确认直接建。
7. **谁能点“创建”。** 和团队设置卡片同一条规则：桌面应用；已配对、有完全访问权限的设备；本机浏览器要等所有机器人都空闲。“取消”谁都可以点。
8. **重新提议。** 用户想改就直接跟主 bot 说，主 bot 再提议一次；同一个对话里它之前那张没回答的卡片立即失效，显示“已被新的提议取代”，不能再点。
   - 所以这张卡片等待时**输入框不锁**（其他确认卡片等待时不能发消息），卡片出现时也不抢键盘焦点，卡片上写着“想改什么，直接在对话里说”。
   - 主 bot 那一轮原本停在旧卡片上等；旧卡片被取代后，它改为等新卡片（和密钥卡片的做法一样，`coordinator.followCard`），所以始终只有一轮在等，用户回答后主 bot 一定收得到。
9. **点“创建”后。**
   - 先核对：卡片上记着提议时模板的版本和文件夹。模板已被删除或改过、或者“新项目放哪”的文件夹换了，就不建，告诉用户和主 bot 重新提议（用户确认的是当时看到的那支团队和那个位置）。
   - 调 `TeamProjectsApi.create({ name, templateId })`，和手动建项目是同一个入口。
   - 成功：卡片变成“项目已创建”，带“打开项目”按钮。主 bot 被叫醒，收到项目名、负责人和需求原文，被要求用现有的 `coordinate_bots` 把需求交给负责人（只交给负责人，不找成员；单向，不等结果；放在负责人名下一个以项目名命名的新对话里），再用一两句话告诉用户。
   - 主 bot 的回复里带进入项目的入口：它被要求把项目写成 `#项目名`，前后各留一个空格。这是应用里机器人提到一个对话的现成写法，界面会把它变成链接，点开就是负责人名下收到需求的那个对话。前后的空格不能省：中文句子里项目名和前后的字连在一起时，界面认不出来（`src/components/team-project-proposal/reply-link.test.ts`）。
   - “打开项目”打开的是同一个对话；那个对话被归档、或者主 bot 还没交接时，打开负责人的对话（和在左侧点它一样）。
   - 被拒绝（`TeamProjectRefusal` 的各个 `code`）：卡片上用平实的话写明原因并失效；主 bot 收到 `code` 和原因，可以换个名字再提议。
10. **点“取消”后。** 卡片显示“已取消”，主 bot 被告知用户取消了，不再重复提议。
11. **重启。** 卡片和它需要的全部内容（项目名、模板编号、需求）都存在对话记录里，重启后仍然可以点，主 bot 那一轮仍然停在卡片上等。用户点了但主 bot 当时没接到结果的，重启后补送一次。
12. **停止。** 用户按“停止”结束主 bot 等待的那一轮，卡片随之关闭（现有做法）。
13. **接真的模块。** `templates` 和 `projects` 两个模块发布后已经合并进来：`server/index.ts` 里那一行把真的模板库（`templateLibrary`）、真的建项目（`teamProjects.api`）和“新项目放哪”（`teamProjects.root`）交给这一块。原来的替身文件已经删掉。

## 接口

```ts
// shared/team-project-proposal.ts（卡片上的数据，随对话记录保存）
export interface TeamProjectProposal {
  requestId: string; botId: string; threadId: string;
  name: string;            // 项目名，也是文件夹名
  folder: string;          // 将要建的文件夹的绝对路径
  template: { id: string; name: string; version: number; genre: string; lead: string; roles: { key: string; name: string; title: string }[] };
  brief: string;           // 用户的需求，建好后交给负责人
  createdAt: number;
  result?: TeamProjectProposalResult;
  resumed?: boolean;       // 主 bot 已经收到结果
}
export type TeamProjectProposalResult =
  | { state: "created"; projectId: string; leadBotId: string; leadName: string; missingSkills: string[] }
  | { state: "cancelled" }
  | { state: "refused"; code: string; error: string };  // code：TeamProjectRefusal，或 "template_changed"、"root_changed"

// server/team-project-proposal.ts
export interface TeamProjectBackends {
  templates: Pick<TemplateLibraryApi, "list">;
  projects: Pick<TeamProjectsApi, "create">;
  projectsRoot(): string | null;
}
export class TeamProjectProposalService {
  templatesText(): string;                                    // list_team_templates 的回答
  propose(input: { botId; threadId; name; templateId; brief }): { requestId; messageId; text };
  respond(args: { threadId; requestId; behavior }, ownerReview: boolean): Promise<{ status; body } | null>;
  decided(threadId, messageId): boolean;
  resume(threadId, messageId, answer: (text: string) => boolean): boolean;
}
export function teamProjectDecisionText(proposal: TeamProjectProposal): string;

// server/team-project-proposal-access.ts
export function proposesTeamProjects(bot): boolean;           // 全局主 bot
```

内部接口（只有主 bot 这一轮的凭证能调）：

- `GET /api/internal/team-templates` → `{ text }`。
- `POST /api/internal/team-project-proposals`，内容 `{ name, templateId, request }` → 201 `{ text, requestId }`；被拒绝时 `{ error }`。

## 需要用户确认的决定

1. **这张确认卡片是 `DESIGN.md`“不新增确认”规则的例外。** `DESIGN.md` 第 2 节不让新增确认卡片；设计文档已经定了“主 bot 建项目要确认”，所以照设计文档做。
2. **需求由主 bot 自己交给负责人。** 点“创建”后程序叫醒主 bot，告诉它项目建好了、负责人是谁、需求原文是什么，要求它用现有的 `coordinate_bots` 交给负责人。交接这一步靠模型照着做：假 AI 的测试里它照做了，真模型没有测过。想要万无一失，可以改成由程序直接把需求发给负责人，不经过模型。
3. **交接是单向的。** 主 bot 把需求交出去就结束，不等负责人的结果，也不替负责人向用户汇报；用户进项目看进展。
4. **需求放在负责人名下一个以项目名命名的新对话里**，不是负责人的主对话（现有的交接机制只能交到工作对话里）。卡片上的“打开项目”打开的就是这个对话。
5. **进入项目的入口有两处：卡片上的“打开项目”按钮，和主 bot 回复里的项目名链接。** 两处打开的都是负责人名下收到需求的那个对话。按钮由程序给出，一定在。链接靠模型照说明把项目写成 `#项目名`（前后各留一个空格）：假 AI 的测试里它显示成链接并能点开，真模型没有测过；模型没照做时回复里就只是一句普通的话。链接是按对话标题找的，所以有两种情况找不对：主 bot 自己名下有一个同名的对话时，链接会指向那个；项目名全是数字时不会变成链接。这两种情况下按钮照常可用。交接在对话里还留下一行“已发送给〈负责人〉”，也能点进去。
6. **卡片等待时输入框不锁，卡片出现时不抢键盘焦点。** 其他确认卡片等待时不能发消息；这张可以，因为设计要求“想改就直接跟主 bot 说”。
7. **只在主 bot 自己的对话里能提议**，群聊里不行。
8. **卡片上不显示需求原文**，只显示项目名、文件夹、团队模板和成员。
9. **谁能点“创建”**：桌面应用；已配对、有完全访问权限的设备；本机浏览器要等所有机器人都空闲。和团队设置卡片是同一条规则。“取消”不限。
10. **确认之后情况变了就不建。** 卡片出来以后模板被改过或删了，或者“新项目放哪”的文件夹换了，点“创建”会被拒绝并提示重新提议。
11. **重名在点“创建”时才发现。** 提议时只检查名字能不能当文件夹名；和已有项目、部门重名由建项目那一步判断，被拒绝后主 bot 换个名字再提议。
12. **不管权限多高都出卡片**，不会自动通过。
13. **长度限制**：项目名沿用建项目的规则（最长 60 个字符）；需求最长 8000 个字符。
14. **通话中不能用语音确认**，只能在屏幕上点。
15. **目标任务的步骤里提议不会停下来等**（团队设置卡片也是这样），那种情况下用户点了之后主 bot 不会被叫醒。目前没有处理。
16. **通过“工具桥接”列工具时**（本机模型，或打开了那个开关），这两个工具不在直接列出的那一小组里，模型要先用 `find_tool` 搜索才用得到。
17. **建成的卡片不变淡。** 其他卡片回答后会变淡；建成项目的卡片上还有“打开项目”按钮，变淡会像是不能点，所以保持原样。
18. **卡片的副标题**（回答栏“详情”里和不认识这种卡片的界面上显示的两行）第二行是“模板名：成员名单”，名单按用户的语言写（中文用顿号和“和”）。

# 漫剧流水线和剪映草稿：设计

日期：2026-11-22 · 状态：待确认

这份文档改写 `2026-11-21-teams-flow-project-canvas-design.md` 的第 4 节"团队流程"，并改动第 5 节"项目画布"里的派发线、分镜节点和自动排列。那份文档的其余部分不变。

每一块在动手前还会有自己的实施计划。

## 为什么

现在的流程是一棵树：参谋长在上，全体成员挂在它下面，工作由上级派给下级，结果回到上级。做漫剧不是这样干的。漫剧是一条流水线：剧本写完交给角色设计，角色和剧本一起交给分镜，分镜拆成镜头，每个镜头生成视频，全部视频齐了交给后期。

- 树表达不了"分镜同时要剧本和角色""后期要等所有镜头"。
- 团队建好后线要自己一条条拖，默认是负责人连所有人，和实际流程对不上。
- 画布上的产物节点由机器人自己决定怎么连，连法不稳定。
- 后期没有落点：视频生成完之后没有下一步。

## 目标

1. 团队的流程是一条流水线，线表示"谁的产出交给谁"。
2. 建团队时线由 AI 自动判定，手动建和主机器人建都一样。
3. 建团队时只有机器人。产物节点在创作中动态出现，怎么连由程序按流水线决定。
4. 工作沿流水线自动接力，批量生成视频之前停一次等你确认。
5. 每个镜头是三个节点：镜头 → 视频创作 → 视频。
6. 所有镜头的视频齐了，后期节点自动生成剪映草稿，素材直接指向项目文件夹里的视频，不复制。
7. 后期节点上有"编辑"按钮，点了打开剪映。成片由你在剪映里导出，导出后回到画布。

## 这一版不做

- 自动导出成片。剪映没有可以调用的导出入口。
- 读回你在剪映里做的修改。剪映保存后的草稿是加密的。
- 接入 OpenCut 或其他内置的视频编辑器。
- 草稿里的字幕、配音、转场、特效。这一版的草稿只有按顺序排好的视频片段，其余在剪映里做。
- 流水线环节的自定义。环节是固定的六种。
- 分集。一个项目是一条流水线，不按集拆分。
- 上游改了以后自动重跑下游。只做标记。
- 纯服务器部署和手机上的剪映草稿。只在装了剪映的 Mac 和 Windows 桌面应用上有。
- 国际版 CapCut。

## 已定的决定

| 问题 | 决定 |
|---|---|
| 流程的形状 | 流水线，一个成员可以有多个上游。取代"一棵树、每人只有一个上级" |
| 线从哪来 | AI 把每个成员对到环节上，线由程序按固定顺序连出来 |
| 自动推进到哪里停 | 剧本、角色、分镜自动接力；批量生成视频之前停一次等你确认；之后自动走到剪映草稿 |
| 负责人经不经手中间结果 | 不经手。它只派给第一环；每一环完成时记一条通知；出问题时由它处理；最后由它向你汇报 |
| AI 判定后能不能改线 | 能。改过的成员不再被自动判定覆盖；团队菜单里有"重新判定" |
| 一个镜头有多个视频 | 每个镜头有一个"选用"的视频，默认是最新成功的那个 |
| 有镜头没成功 | 不进入后期，通知你和负责人 |
| 后期用什么 | 生成剪映草稿。不用 ffmpeg，不接 OpenCut |
| 成片怎么出 | 你在剪映里点导出 |

下面几项是我定的默认做法，还没有单独问过你，不同意请指出：

| 问题 | 默认做法 | 原因 |
|---|---|---|
| "视频创作"节点 | 用现有的"生成配置"节点，不新增类型 | 它本来就是"汇总上游、带模型和参数、点生成" |
| 角色 | 一个组：一个设定文字节点加它生成的参考图 | 不新增节点类型 |
| 同一环节有多个成员 | 都收到这一环的任务；全部做完才算这一环完成 | 规则最简单，不用再判定怎么分工 |
| 一个成员对到多个环节 | 合并成一个节点，依次做这几环 | 截图里的"分镜与美术设计"就是这种 |
| 缺了某个环节 | 跳过，上一环直接连下一环 | 团队可以很小 |
| 流水线之外的成员 | 挂在负责人下面，由负责人按现在的方式派活 | 比如运营、配音 |
| 不是漫剧的团队 | 全员判成"其他"，结果和现在一样：负责人连所有人 | 不影响其他用途 |
| 上游改了、下游已经做完 | 下游节点显示"上游有更新"，不自动重做 | 重做要花钱，由你决定 |
| 重新生成草稿 | 剪映没保存过的草稿原地更新；保存过的不动，另存一份带序号的 | 不丢你在剪映里的修改 |
| 判定用哪个模型 | 配了决策模型就用它；没配就用主机器人的模型在后台判定一次；都不可用时按职责里的关键词判定 | 没配任何东西也能用 |

## 名词

- **负责人**：团队的参谋长。流水线的起点。
- **环节**：成员在流水线上的位置。六种：负责人、编剧、角色设计、分镜、后期、其他。
- **流水线**：按环节顺序连起来的线。
- **流程线**：画布和团队地图上机器人之间的线，来自流水线。取代原来的"派发线"。
- **运行**：一次从负责人接到任务到剪映草稿生成的过程。
- **时间线**：程序保存的一份清单：镜头的顺序，每个镜头选用哪个视频。
- **剪映草稿**：按时间线写进剪映草稿目录的一个文件夹。

## 设计

### 1. 流水线的形状

环节的顺序是固定的：

```text
负责人 → 编剧 → 角色设计 → 分镜 → 后期
            └──────────────→ 分镜
```

线由程序按每个成员的环节连出来，规则：

- 负责人连到最靠前的那个有人的环节。
- 相邻的两个有人的环节之间，前一环的每个成员连到后一环的每个成员。
- 编剧和分镜之间隔着角色设计时，编剧另有一条线直接连到分镜，因为分镜既要角色也要剧本。
- "其他"环节的成员只和负责人相连。
- 负责人永远是团队的参谋长，不由 AI 判定。

例子，截图里的团队（云舟 制片人、砚青 编剧、墨白 分镜与美术设计、青禾 后期合成）：

```text
云舟 → 砚青 → 墨白 → 青禾
```

墨白同时是角色设计和分镜，两环合在它一个节点上。

### 2. AI 判定

**判定什么**

只判定每个成员属于哪个或哪几个环节。依据是它的名字、职责、说明和人设。线不由 AI 画。

**什么时候判定**

- 主机器人建团队：它在提案里写明每个成员的环节。确认卡片上显示连好的流水线，你点确认才建。提案里没写环节的成员，建好后按下面的方式判定。
- 手动建团队：团队有了参谋长之后，成员加入、离开，或者职责、说明、人设改了，后台重新判定这个团队里没被你改过的成员。
- 判定在后台做，不弹窗，不挡操作。线判好了直接出现在团队地图上。

**手动改**

- 在团队地图里，从一个机器人卡片右侧的圆点拖到另一个成员，就加一条线；点一条线可以去掉。
- 会形成回路时拒绝，并说明原因。负责人不能有上游。
- 你改过线的成员记为"手动"，之后的自动判定不再动它。
- 团队的菜单里有"重新判定"：清掉手动标记，全部重新判定。可以撤销。

**判不出来时**

判定失败或者超时，成员先记为"其他"，挂在负责人下面，下次有变化时再判。团队始终是能用的。

### 3. 接力

工作由程序沿流水线往下送，不靠机器人自己转交。

**一次运行**

1. 你在画布上给负责人下任务，或者主机器人建项目时把你的要求交给负责人。
2. 负责人写出创作要求，派给第一环。从这里开始算一次运行。
3. 一环的所有成员做完后，程序把这一环的产出交给下一环的每个成员，作为一条任务消息，产出作为参考内容带上。
4. 一环的上游有多个时，等全部上游做完才开始。分镜等剧本和全部角色；后期等所有镜头的视频。
5. 分镜做完后，程序给每个镜头放好"视频创作"节点，然后停下，发一张卡片：有几个镜头、要生成几段视频。你点"开始生成"才继续。
6. 所有镜头都有选用的视频后，程序建好时间线，生成剪映草稿，后期环节开始。
7. 后期机器人核对时间线（顺序、缺的镜头），需要时调整顺序，然后交付。程序更新草稿。
8. 负责人收到"草稿已生成"，向你汇报。运行结束。

**每一环交什么**

| 从 | 到 | 交的是 |
|---|---|---|
| 负责人 | 编剧 | 创作要求 |
| 编剧 | 角色设计、分镜 | 剧本 |
| 角色设计 | 分镜 | 全部角色的设定和参考图 |
| 分镜 | 视频创作 | 每个镜头的提示词和它用到的角色参考图 |
| 视频 | 后期 | 每个镜头选用的视频 |

**"做完"的意思**

- 机器人的环节：它为这条任务开的那一轮正常结束。它在等你回答问题或审批时不算做完，你回答后继续。
- 镜头：有一个生成成功并被选用的视频。

**负责人**

- 每一环做完，在负责人的对话里记一条通知。通知只是记录，不让负责人开始新的一轮。
- 一环失败时，负责人收到通知并开始一轮，由它决定重试、改要求，还是来问你。
- 运行结束时，负责人开始一轮，向你汇报。

**出问题时**

- 机器人的一轮失败或被停止：运行停在这一环，节点显示出错，可以在节点上重试。
- 有镜头生成失败：其他镜头照常生成。全部结束后运行停在这里，通知你和负责人。你可以重试失败的镜头，或者去掉它再继续。
- 你中途直接给某个机器人下任务、改了某个产物：不打断运行。它下游已经做完的节点显示"上游有更新"。

**你自己的操作不受限制**

你可以随时在画布上给任何一个机器人下任务，可以手动点任何一个生成按钮。流水线只管自动接力这一条路。

### 4. 机器人能联系谁

- 流水线里的成员能联系它的上游和下游，只用来问问题。它不能把自己的环节转交给别人。
- 负责人能把工作派给第一环和"其他"环节的成员。
- 这些规则和现在一样由程序限制，加在同一处判断上（`server/peer-roster.ts`）。提示词（`server/chief-of-staff.ts`）跟着改写。
- 你自己不受限制。

### 5. 画布

**流程线**

机器人之间的线来自流水线，在画布上不能改，要改去原团队。样式和内容线不同。项目不保存流水线的副本，每次用到时从原团队换算到分身上。

**动态出现的节点怎么连**

由程序按"谁做的、是什么"来连。机器人不用自己连，也改不了这些线。

| 出现的节点 | 谁产生 | 程序自动连到 |
|---|---|---|
| 剧本（文本） | 编剧 | 从编剧连过来；连到角色设计和分镜 |
| 角色（一个组：设定加参考图） | 角色设计 | 从角色设计连过来；连到分镜 |
| 镜头 | 分镜 | 从分镜连过来 |
| 视频创作 | 程序，每个镜头一个 | 从镜头连过来；镜头用到的角色参考图也连到它 |
| 视频 | 生成完成 | 从视频创作连过来；选用的那个连到后期 |
| 剪映草稿、成片 | 后期 | 从后期连过来 |

**镜头的三个节点**

- **镜头**：这个镜头的画面描述。分镜机器人放的，可以改。
- **视频创作**：模型、分辨率、比例、时长，以及参考图。默认继承项目的全局配置，可以单独改。"生成"按钮在这里。
- **视频**：生成的结果，可以播放。再生成一次，新视频排在旧的下面，旧的保留。
- 一个镜头有多个视频时，选用的那个有标记。在视频节点上点"选用"可以换。

镜头节点上原来的"生成视频"按钮去掉，生成都从视频创作节点走。

**排列**

机器人按环节从左到右排成一行，同一环节的上下排列。每个机器人的产物在它右边、下一环的左边。镜头从上到下排，每个镜头的三个节点在同一行。"整理"按这个规则重排。

### 6. 后期和剪映草稿

**时间线**

程序为每个项目保存一份时间线：镜头的顺序，每个镜头选用的视频文件。镜头的顺序默认是分镜机器人放镜头的顺序。后期机器人有两个工具：读时间线、调整顺序或去掉某个镜头。

**生成草稿**

- 草稿目录从剪映自己的配置里读（Mac 上默认是 `~/Movies/JianyingPro/User Data/Projects/com.lveditor.draft`）。
- 在里面建一个以项目名命名的文件夹，写两个文件：时间线文件和草稿信息文件。
- 时间线文件里，每段视频按绝对路径指向项目文件夹里的文件。不复制素材。
- 画面尺寸和帧率取第一段视频的。
- 片段首尾相接，不裁剪，速度不变。

**什么时候生成**

- 所有镜头都有选用的视频时，自动生成。
- 之后时间线变了（换了选用的视频、调了顺序、重做了镜头），自动更新。
- 更新前先看草稿是不是还是我们写的那一份：是，原地更新；不是，说明剪映保存过，原来那份不动，另存一份名字带序号的。

**后期节点**

- 草稿生成后，节点上显示草稿的名字和"编辑"按钮。
- 点"编辑"打开剪映。能直接打开那份草稿就直接打开；做不到时打开剪映，节点上写明草稿叫什么。
- 没装剪映时按钮不能点，并说明要先装剪映。
- 这个应用在操控另一台电脑时没有这个按钮，因为草稿在那台电脑上。

**成片回到画布**

- 草稿生成后，节点上写明"在剪映里导出到这个文件夹"，旁边可以复制项目 `产出` 文件夹的路径。
- 程序看着 `产出` 文件夹。出现一个不是我们生成的视频文件时，它成为"成片"节点，连在后期节点后面，并通知负责人。
- 也可以在后期节点上点"选择成片"，手动选一个文件。

### 7. 存放和升级

- 流水线存在服务器的数据目录里（`team-flows.json`），按团队记录每个成员的环节、是不是手动改过，以及你手动加减的线。
- 时间线存在程序的数据目录里，和画布文档放在一起。
- 升级时：已有的团队自动判定一次。原来手动拖过上下级的成员，那条线保留并记为"手动"。
- 已有项目的画布保留。流程线按新的流水线重画；原来的镜头节点各补一个视频创作节点，已有的视频接在后面。

## 安全

- 写剪映草稿只写草稿目录下以项目名命名的文件夹，不改剪映的其他文件。项目名里的路径符号先去掉。
- 草稿里只写项目文件夹内的文件路径。
- 判定环节时交给模型的只有成员的名字、职责、说明和人设，不带对话、记忆和密钥。
- 程序发给机器人的任务消息带明确的来源标记，和现有的交接消息一样，机器人把它当任务而不是你说的话。
- 成片只认项目 `产出` 文件夹里的视频文件，按内容判断类型，不按扩展名。

## 分块和顺序

1. **流水线模型**：环节、连线规则、存储、升级、团队地图上画线和显示。
2. **AI 判定**：主机器人的提案带环节；手动建团队时后台判定；重新判定。
3. **联系规则和提示词**：上游下游只问问题，负责人派第一环。
4. **画布**：流程线、排列、镜头的三个节点、选用、角色组、自动连线。
5. **接力**：运行、等齐、确认卡片、失败处理、给负责人的通知。
6. **剪映草稿**：时间线、生成和更新草稿、"编辑"按钮、成片回到画布。

第 1 到 3 块做完，团队地图上就是流水线。第 4、5 块做完，项目能自动跑到所有视频生成完。第 6 块做完，能进剪映出成片。

## 风险和还没验证的事

- **剪映 11.8 认不认我们写的草稿，只验证了一半。** 测试草稿放进去后，剪映把它登记进了草稿列表（名字和时长都对）。能不能打开、素材能不能播放还没验证。打不开的话第 6 块要换做法。
- **剪映的草稿格式不公开**，升级后可能变。写草稿的代码要集中在一处，带版本检查，认不出的版本不写并说明原因。
- **"点编辑直接打开那份草稿"还没找到办法。** 找不到就只打开剪映。
- **Windows 上的草稿目录和文件名**和 Mac 不同，还没在 Windows 上试过。
- **素材路径会失效**：项目文件夹移动、改名，或者外接硬盘拔掉后，剪映里显示素材丢失。
- **没配决策模型时的后台判定**要占用主机器人的模型一次调用，每次成员变化都会触发，要做合并和限流。
- **把树改成流水线牵动面大**：流程的存储、联系规则、提示词、画布排列和已有的测试都要改。

## 怎么验证

- 每一块配单元测试；牵涉服务器的配端到端测试，在隔离的假引擎环境里跑，不碰你正在用的应用和数据。
- 判定：用截图里的四人团队、一个标准的五人团队、一个不是漫剧的团队各判一次，核对连出来的线。
- 接力：在假引擎环境里从负责人下任务，走到确认卡片；确认后走到草稿生成。中间故意让一个镜头失败、让一个机器人失败，各验证一次。
- 剪映草稿：在这台 Mac 上生成草稿，由你在剪映里打开、播放、导出，确认成片回到画布。这一步需要你动手，我替不了。

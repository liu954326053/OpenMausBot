# 团队即模板、团队流程和项目画布：设计

日期：2026-11-21 · 状态：已确认，按分块连续实施

这份文档改写 `2026-11-20-projects-templates-skills-design.md` 里的"模板库"和"模板同步"两部分，并新增团队流程和项目画布。那份文档里的技能库、MCP 入口、项目文件夹、项目隔离和归档不变。

每一块在动手前还会有自己的实施计划。

## 为什么

上一版要求在"模板"页里用表单准备机器人模板和团队模板，还要给每个角色指定技能和 MCP。实际用下来不顺手：

- 建机器人有两套方式，一套在左侧，一套在模板页的表单里。
- 团队明明已经在左侧建好了，还要再填一遍才能用来建项目。
- 技能和 MCP 应该由机器人按任务自己选，不该在建模板时指定。
- 打开项目看到的是一个个对话，看不出谁在做什么、做出了什么。

## 目标

1. 正常建好的团队就是模板。建项目时直接选一支团队。
2. 项目里的机器人是团队成员的分身：对话、记忆、学到的技能和工作文件夹都在项目里，项目之间不相通。
3. 原团队的设定一改，各项目里的分身自动跟着变。
4. 左侧只有主机器人、收件箱和项目列表。
5. 主机器人不属于任何部门，可以按需求建团队、建项目。
6. 团队的流程是一棵树：参谋长是根，每个成员只有一个上级，可以有多个下级，工作由上级派给下级。
7. 打开项目看到的是画布。画布和节点的逻辑完全参考 infinite-canvas，把团队和机器人融进去：机器人是节点，输出显示在节点里；点一个节点，它下方出现这类节点自己的面板。
8. 图片和视频的生成都通过 MCP。模型列表从 MCP 取；项目有全局配置，节点默认继承，也可以单独改。

## 这一版不做

- 同一个机器人在多个项目里共用（每个项目里是分身）。
- 把原机器人的记忆、对话带进项目。
- 在项目里单独修改分身的名字、职责、人设、外观、模型。
- 在项目里单独修改流程。流程只在原团队里改。
- 机器人之间一个成员有两个上级，或者有两个参谋长。
- 角色、场景、配音这几类节点。节点类型以后再加。
- infinite-canvas 里的助手面板、提示词库、"我的资产"页面、WebDAV 同步和节点插件。
- 多人同时编辑同一张画布。

## 已定的决定

| 问题 | 决定 |
|---|---|
| 团队从哪来 | 左侧或团队地图里正常建的团队都能用来建项目。设置里的"模板"页去掉 |
| 项目里的机器人 | 分身。名字、职责、说明、人设、外观、模型自动跟随原机器人，在项目里只读 |
| 技能和 MCP | 不按角色指定。机器人自己选用技能库里启用的技能和开着的 MCP |
| 项目参谋长 | 每支团队自己设一位参谋长。主机器人不当项目参谋长 |

| 分镜和视频 | 是两种节点。分镜节点生成后，它右边出一个视频节点 |

| 模型配置 | 项目有全局配置，入口是画布右上角工具栏的设置按钮。节点默认继承全局的，用户可以在节点上改 |
| 谁来触发生成 | 用户可以在节点上手动点；机器人也能触发 |
| 用哪个 MCP 服务器 | 还没定。先做前面几块；第 6 块先按本文档里的约定做，定下服务器后再对接 |
| 怎么推进 | 方案确认后按分块连续做完，中间不停下来问。每一块做完打包到备用位置，不动正在运行的应用；换上新版之前仍然先问 |

下面几项是我定的默认做法，还没有单独问过你，不同意请指出：

| 问题 | 默认做法 | 原因 |
|---|---|---|
| 文本节点怎么生成 | 面板里选一个机器人来写或改写，不接文本模型 | 写文字本来就是机器人的工作 |

| 画布代码 | 移植 infinite-canvas 的画布核心，保留它的版权声明。界面控件和样式用 MagicBot 自己的 | 它是 MIT 许可；不引入它用的 Ant Design |

## 名词

- **主机器人**：MagicBot。不属于任何部门，也不属于任何项目。
- **团队**：一个部门，有一位参谋长和若干成员。在团队地图里管理。
- **项目**：一部短剧。对应一个项目文件夹和一支由分身组成的团队。
- **分身**：建项目时照着团队成员生成的机器人。它记着自己的原机器人是谁。
- **流程**：团队里谁是谁的上级。它是一棵树，参谋长是根。
- **节点**：画布上的一个方块。有类型，每种类型显示的内容和下方的面板不同。
- **派发线**：机器人之间的上下级连线。
- **内容线**：其他连线。上游节点是下游节点的参考内容。
- **项目全局配置**：一个项目里图片和视频生成默认用的 MCP 服务器、模型和参数。

## 设计

### 1. 团队即模板

**哪些团队能用来建项目**

同时满足这三条：

- 至少有一个机器人。
- 有一位参谋长，而且不是主机器人。
- 它本身不是某个项目的团队。

"新建项目"窗口列出所有团队。不满足条件的也列出来，但不能选，并写明原因，比如"它还没有能带领项目的参谋长"。没有参谋长的团队旁边有"选择参谋长"，选好后这支团队立刻能选。建好后打开新项目的画布。

**建项目的步骤**

和现在相比，只有第 3 到第 6 步变了。

1. 用户给出项目名，选一支团队。
2. 检查项目名、项目根目录和重名，规则不变。
3. 用现有的"共享"导出把团队导出成一份内存里的团队文件。导出不带对话、记忆和密钥。
4. 用现有的导入在项目文件夹里生成一支新团队。每个分身记下自己的原机器人。
5. 原团队参谋长的分身成为项目参谋长。
6. 分身的模型取原机器人当前的模型。不分配技能，不设 MCP 清单。
7. 原机器人自己学到的技能随导出复制一份给分身。之后不跟随。
8. 原团队的例行任务复制过来，初始为暂停。
9. 记入项目清单。项目记下它来自哪支团队。

任何一步失败，撤销已经做的部分，规则不变。

**自动跟随**

原机器人的这些项一改，它在所有项目里的分身立刻改成同样的值：

- 名字、职责、说明、人设
- 外观：颜色、吉祥物、头像图片和裁剪
- 模型

团队这一层跟随的有两项：背景说明和流程。

规则：

- 正在进行的那一轮对话不受影响，下一轮开始用新设定。
- 分身的这几项在项目里只读。界面上显示"跟随 猫漫剧 的 Mochi"，旁边有"去原团队修改"。
- 服务器拒绝任何对这几项的直接修改，包括项目参谋长用 `propose_profile`、`propose_model` 提出的修改，并说明要去原团队改。
- 项目里同名时，沿用现有的加序号规则。

**原机器人不在了**

原机器人被删除或被移出团队后，分身留在项目里，变成项目自己的成员：不再跟随，那几项可以直接改。项目里会提示。

**团队成员增减**

项目随时比较"分身的原机器人"和"原团队现在的成员"：

- 团队里有、项目里没有的：新增成员。
- 项目里有、但原机器人已不在团队里的：已离开的成员。

有差别时，项目画布顶部显示"团队有变化"。点开后列出每一项，用户逐项勾选：

- 新增成员：加进项目，生成分身。
- 已离开的成员：移出项目，或者留下当项目自己的成员。

移出项目时，分身被删除，它在项目文件夹里的记忆文件夹按现有做法移到 `.deleted` 下，不真正删除。

**以前按模板建的项目**

照常能用。它们没有原团队，所以成员都是项目自己的成员：不跟随，可以直接改；流程是默认的树，所有成员都是参谋长的下级。磁盘上已有的模板文件不动。

### 2. 主机器人

**不属于任何部门**

- 主机器人不能被放进任何部门。拖动、设置、团队设定这几条路都拒绝，并说明原因。
- 新版第一次启动时做一次迁移：主机器人如果在某个部门里，就移出来。迁移前先备份机器人数据文件，迁移结果写进日志。
- 如果它原来是那个部门的参谋长，移出后那个部门没有参谋长。团队地图在这个部门上提示"没有参谋长"，点它就能从这个部门的成员里选一位。收件箱里由主机器人发一条"待你处理"的提示，只发一次，部门有了参谋长就自动完成。Team Cloud 没有收件箱，不发这条提示。

**能力**

- **建团队和机器人**：用现有的 `propose_team_setup`，出确认卡片。提示词里加一条：给项目用的新团队必须指定一位参谋长。现有的 `create_bot` 是不出卡片、直接创建、事后可撤销的，主机器人不再使用它，统一走确认卡片。
- **建项目**：现有的两个工具改成面向团队。
  - `list_team_templates` 改为列出能用来建项目的团队：名称、背景说明、参谋长和成员的职责。
  - `propose_team_project` 改为给出项目名、选的团队和用户的需求。
- **没有合适的团队时**：先用 `propose_team_setup` 提议建一支新团队，用户确认后再提议建项目。
- **技能**：始终列出技能库里启用的全部技能，不受"只列最相关的 15 个"的限制。
- **MCP**：没有自己的清单，所以用全部开着的 MCP。这是现有行为。

**不变的规则**

主机器人只和各项目的参谋长联系，不直接指挥项目成员。它不出现在项目画布上。

### 3. 左侧和团队地图

**左侧从上到下**

1. 主机器人
2. 收件箱
3. 项目列表。每个项目一行，点一下打开项目画布。搜索时也一行一个：项目名、它的机器人或群聊搜得到，项目就留下，行下面不列任何东西；搜到的是项目里的机器人或群聊时，行上项目名后面用浅色写出它们的名字，点行打开画布并选中搜到的机器人（几个都搜到时先选参谋长）。
4. 新建项目
5. 底部的"工具"，不变

去掉的分组：部门、机器人、群组聊天、机器人对话、已置顶。

**顶部的创建入口**

保留三项：新建项目、创建机器人、创建部门。建好机器人或部门后，直接打开团队地图并定位到它。

**团队地图**

团队地图成为管理团队的地方。它已经能打开对话、编辑机器人、移动机器人、管理部门。要补的：

- "添加"菜单里加"创建机器人"，用和左侧相同的新建窗口。
- 部门没有参谋长时在部门上提示。提示本身和部门的"⋯"菜单里的"选择参谋长"都能直接选；在哪里选了参谋长，提示都立刻消失。
- 部门的"⋯"菜单里有"用这个团队新建项目"，打开"新建项目"窗口并选好这支团队。
- 机器人卡片上显示未读圆点。
- 项目的团队不显示在团队地图里，它们在各自的项目画布里。

**项目之外的未读**

原团队的机器人、零散的机器人和项目外的群聊有未读时，底部"团队地图"入口上显示圆点。需要你处理的事（审批、提问）仍然进收件箱，这是现有行为。

### 4. 团队流程

**是什么**

流程规定团队里谁是谁的上级。它是一棵树：

- 参谋长是根，没有上级。
- 其他每个成员有且只有一个上级，可以有多个下级。
- 没有特别指定时，成员的上级就是参谋长。所以一支新团队的默认流程是：参谋长下面挂着全体成员。

例子：参谋长下面是选题、编剧、分镜三位成员；也可以让分镜下面再挂一位专门做视频的成员。

**怎么画**

在团队地图里：从一个机器人卡片右侧的圆点拖到另一个成员卡片上，后者就成为前者的下级。

- 成员原来的上级被替换，因为上级只能有一个。
- 会形成回路时拒绝，并说明原因。
- 参谋长不能成为别人的下级。
- 去掉一条线后，那个成员回到参谋长下面。
- 成员被删除或移出团队时，它的下级改挂到它原来的上级下面。

**存放**

流程存在服务器的数据目录里（`team-flows.json`），按团队记录每个成员的上级，因为机器人要读它。成员卡片在团队地图上的位置仍然存在本机，和现在一样。

**项目里的流程**

项目不保存流程的副本。每次用到时，把原团队的流程换算到分身上。所以改了原团队的流程，各项目立刻跟着变。分身的原机器人不在流程里时，它挂在项目参谋长下面。

**派发规则**

- 机器人只能把工作派给自己的直接下级。这条规则由程序限制，加在机器人互相联系的那一处判断上（`server/peer-roster.ts`）。
- 下级做完，结果回到派给它的上级。这是现有交接机制的行为，不用改。
- 机器人的同事名单里只列它的上级和下级。
- 这条规则只管机器人。你自己可以在画布上直接给任何一个机器人下任务。

现有的交接记录本身就是一棵树（每次交接记着它的上一级），所以流程、交接记录和画布上的派发线三者的形状是一致的。

### 5. 项目画布

**原则**

画布和节点的逻辑完全参考 infinite-canvas，把团队和机器人融进去。和它不同的只有四处：

- 多了一种节点：机器人。
- 文字由机器人写，不是由文本模型直接生成。
- 图片和视频的生成走 MCP，不是浏览器直连模型接口。
- 画布存在服务器上，不是浏览器里，因为机器人也要读写它。

**示意图**

```text
┌ 图片 ──────────┐
│ 人物设定图.png │┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┐  内容线：上游是下游的参考内容
└────────────────┘                                 ┆
                       ┌ 机器人 · 编剧 ─┐          ┆
                  ┌━━━▶│ Tango  第 1 集… │          ▼
┌ 机器人 · 参谋长 ┐┃    └────────────────┘   ┌ 分镜 · 镜头 2 ──────┐
│ Nori  已分给…   │┫    ┌ 机器人 · 分镜 ─┐ ┌▶│ 近景，掀开头纱…     │
└─────────────────┘┗━━━▶│ Scout  拆成 2…  │─┤ │ 5 秒 · 1080p · 模型 │
   派发线：机器人之间    └────────────────┘ │ └─────────────────────┘
   的上下级，一棵树                          │ ┌ 分镜 · 镜头 1 ──────┐   ┌ 视频 ───────┐
                                             └▶│ 教堂全景，晨光…     │──▶│ 镜头 1.mp4  │
                                               └─────────────────────┘   └─────────────┘
```

**照搬 infinite-canvas 的部分**

- **画布**：平移、缩放、网格、点阵或空白背景、小地图、重置视图、缩放条、居中聚焦。
- **节点**：拖动、四角缩放、标题改名、左右连接点、选中高亮、相关上下游高亮、节点上方的操作栏、节点下方的面板。面板点了节点才出现，大小不随画布缩放变化。
- **连线**：从一个节点右侧的连接点拖到另一个节点；上游是下游的参考内容；一个节点可以有多个上游；点线可以删除。
- **选择和编辑**：框选、多选、全选、复制粘贴、删除、打组和解散、撤销和重做。
- **底部工具栏**：新建文本、图片、视频、音频、生成配置、组，上传文件，画布外观，清空。
- **生成**：空节点生成时结果回填到当前节点；已有内容时结果出现在右边的新节点里并自动连上；一次生成多个时是一组；失败可以重试。
- **面板里的引用**：用 `@` 引用已经连到这个节点的内容。
- **左侧的节点列表**：搜索和定位节点，可以收起。

**不照搬的部分**

- 右侧的助手面板。它的作用由机器人节点代替。
- 提示词库、"我的资产"页面、WebDAV 同步、节点插件。
- 浏览器本地存储。
- Ant Design 界面库。控件和样式用 MagicBot 自己的。

**节点类型**

| 类型 | 节点里显示 | 下方的面板 |
|---|---|---|
| 机器人（新增） | 头像、名字、状态、它最新的输出文字 | 参考内容、输入框、发送；对话记录 |
| 文本 | 正文 | 输入要求，选一个机器人来写或改写 |
| 图片 | 图片本身；还没生成时显示提示词和参数 | 提示词、参考图、模型、比例、清晰度、数量、"生成" |
| 分镜（新增） | 提示词、时长、分辨率、模型，以及有几个参考 | 提示词、参考图、参考音频、模型、分辨率、比例、时长、"生成视频" |
| 视频 | 视频本身，可以播放；还没生成时显示提示词和参数 | 提示词、参考图、参考音频、模型、分辨率、比例、时长、"生成" |
| 音频 | 文件名、时长，可以播放 | 改名、下载 |
| 生成配置 | 汇总的上游文本和图片、模型和参数 | 模型、参数、输入顺序、"生成" |
| 组 | 包住的一组节点 | 解散 |

**分镜节点**

- 一个镜头一个分镜节点。分镜机器人把它们放在自己的右边并连好线；用户也可以从底部工具栏自己新建。
- 节点里显示这个镜头的提示词、时长、分辨率、模型，以及有几个参考。
- 面板里可以改提示词、时长、分辨率、比例和模型；参考图和参考音频来自连到它的图片节点和音频节点。
- 点"生成视频"后，它右边出现一个虚线的"生成中"视频节点并连好线，完成后变成视频。
- 改了参数再生成，新视频排在旧视频下面，旧的保留。
- 视频节点保持 infinite-canvas 的行为：用户自己新建的空视频节点也可以直接填提示词生成。

**机器人节点**

- 节点里直接显示它最新的输出文字，按 Markdown 排版。放不下时底部渐隐，可以拖动节点的角放大。
- 工作中时显示当前这一步在做什么，沿用现有的活动摘要。
- 状态：工作中、排队中、等你回复、空闲、出错。
- 连到它的内容节点是它的参考内容，和其他节点的规则一样。
- 它交出的文件（`attach_file`）和它放的节点，出现在它右边并自动连上。
- 下方的面板：
  - 参考内容：连到它的节点，显示成标签。
  - 输入框：发给这个机器人在本项目里的对话。参考内容随消息一起带上：文本带文字，图片、音频、视频作为附件。
  - 发送按钮。工作中时变成停止。
  - 机器人在等你回复时，它的提问或审批卡片显示在面板里。
  - "对话记录"：点了才在面板里展开最近的来往，并可以打开完整对话。
- 模型不在这里选。机器人的模型跟随原团队里的原机器人。
- 机器人节点不能删除、复制或打组。增减成员走"团队有变化"或项目的成员管理。
- 给项目下任务，就是点参谋长节点，在它下方输入。

**两种线**

- **派发线**：机器人之间的上下级，来自团队流程，是一棵树，只有参谋长一个根。它在画布上不能改，要改去原团队。样式和内容线不同，一眼能分开。
- **内容线**：infinite-canvas 原有的连线。内容节点之间可以连，内容节点也可以连到机器人。一个节点可以有多个上游。

**自动排列**

- 机器人按派发线排成一棵从左到右的树：参谋长在最左，下级在右边一列，每棵子树占自己的一段高度。
- 机器人做出来的节点排在它右边。
- 用户新建或上传的节点出现在视野中间，由用户自己摆放。
- 所有位置随项目保存。"整理"只重新排机器人这棵树和它们做出来的节点。

**机器人怎么操作画布**

参考 infinite-canvas 给 Codex 的那组工具，项目里的机器人多一组工具：

- 读画布：全部节点和连线的摘要，或者只读连到自己的内容。
- 批量操作：新建节点、修改节点、连线、删除节点。
- 触发生成：让一个图片节点或视频节点开始生成。

规则：

- 机器人只能修改和删除它自己放的节点，可以读全部节点。
- 放节点不需要用户确认，因为不合适可以直接删，也可以撤销。
- 机器人的文字回复自动显示在它自己的节点里，不用调用工具。

**模型和生成**

- 图片生成和视频生成都通过 MCP。
- 模型列表从 MCP 服务器取。
- **项目全局配置**：画布右上角工具栏有一个设置按钮。里面配置：
  - 图片：用哪个 MCP 服务器、默认模型、默认比例、清晰度、数量。
  - 视频：用哪个 MCP 服务器、默认模型、默认分辨率、比例、时长。
- **节点继承全局配置**：
  - 节点没改过的项用全局配置，全局一改它跟着变。
  - 在节点面板里改了某一项，这个节点的这一项就固定下来，不再跟着全局变。
  - 可以"恢复默认"，重新跟随全局。
- 新项目的全局配置沿用你上一次保存的。
- 每个模型能选哪些分辨率、时长，以 MCP 服务器给出的为准；没给出时用固定的常见选项。
- 不管是用户点"生成"，还是机器人触发，都走程序里的同一条路：程序把节点的提示词、参考内容和参数原样交给 MCP 工具，等结果，把文件存进项目文件夹，再更新节点。这样参数不会被模型改写，画布也一定会更新。
- 视频生成需要几分钟。期间节点显示"生成中"，可以取消。失败时节点显示原因，可以重试。

**和 MCP 服务器的约定**

用哪个 MCP 服务器还没定。第 6 块先按下面的约定做，并用一个测试用的 MCP 服务器验证。定下真正的服务器后，只改对接这一层。

程序需要服务器上有四个工具。项目全局配置里可以把每一项对应到服务器上实际的工具名：

| 用途 | 交给它 | 它返回 |
|---|---|---|
| 列出模型 | 无 | 每个模型的编号、名称、类别（图片或视频），以及它能选的分辨率、比例、时长，是否支持参考图和参考音频 |
| 生成图片 | 模型、提示词、参考图、比例、清晰度、数量 | 图片文件，或者一个任务编号 |
| 生成视频 | 模型、提示词、参考图、参考音频、分辨率、比例、时长 | 一个任务编号 |
| 查询任务 | 任务编号 | 状态、结果文件的地址、失败原因 |

没有配置 MCP 服务器时，生成按钮不能点，并说明要先在项目全局配置里选服务器。

**存放**

- 每个项目的画布是一份保存的文档：节点、连线、位置、视口、分组、项目全局配置。它存在程序的数据目录里，不放在项目文件夹里，因为机器人只能通过工具改它。
- 上传的文件存在项目文件夹的 `素材` 目录下，生成的图片和视频存在 `产出` 目录下。画布只记它们的路径。
- 机器人节点和派发线不存在画布文档里，每次从项目的成员和流程算出来；文档里只存机器人节点的位置和大小。

**画布接口**

- 只返回查看者本来就能打开的对话里的内容。
- 机器人的输出文字经过现有的密钥遮盖。
- 画布打开时，有新事件立即更新，沿用现有的事件推送（`/api/events`）。

### 6. 去掉的东西

- 设置里的"模板"页，以及机器人模板和团队模板的编辑窗口。
- "存为模板""从模板更新""存回模板""沉淀到模板"。
- 模板库和模板同步的接口。
- 建项目时按角色分配技能、设置 MCP 清单的步骤。

保留：

- "把学到的技能沉淀到技能库"。
- "共享"导出和团队文件导入，建项目在内部继续用它们。
- Team Cloud 自己的模板列表。那是另一项功能，不动。

## 安全

- **自动跟随会放大误改。** 原机器人的人设改错了，所有项目里的分身立刻跟着错。应对：人设编辑沿用现有的撤销；分身只跟随上面列出的几项，权限等级不跟随。
- **人设仍然不放在机器人能改的地方。** 规则不变。分身的人设由程序从原机器人写入，机器人自己改不了。
- **画布文档不放在机器人能直接改的地方。** 机器人只能通过工具改它自己放的节点。
- **机器人放的节点内容来自模型。** 镜头的提示词可能受它读过的网页或文件影响。生成图片和视频会花钱，所以机器人触发生成时，一次最多生成的个数有上限，超过要用户确认。
- **生成接口的密钥。** 由 MCP 服务器保管，沿用现有的 MCP 密钥存放方式，不进画布文档，不进对话。
- **画布接口带对话内容。** 必须按查看者能看到的范围过滤，并遮盖密钥。
- **主机器人建团队、建项目都要用户确认。** 规则不变。
- **主机器人的迁移会改用户数据。** 只做一次，先备份，结果写日志。迁移失败时不动数据，下次启动再试。
- **项目隔离不变。** 分身只能联系本项目里自己的上级和下级；原团队的机器人看不到项目里的分身。

## 分块和顺序

每一块做完都能单独用，都在独立的测试实例上验证，打包后先问你再换上。

| 顺序 | 块 | 做完后能做什么 |
|---|---|---|
| 1 | 团队即模板和主机器人 | 直接选一支团队建项目；分身自动跟随；主机器人移出部门，能按需求建团队和项目；模板页去掉 |
| 2 | 左侧和团队地图 | 左侧只有主机器人、收件箱和项目；团队地图里能创建机器人 |
| 3 | 团队流程 | 在团队地图里画出上下级；项目里的机器人只能派给直接下级 |
| 4 | 画布和机器人节点 | 打开项目看到画布；机器人按派发线排成一棵树，节点里显示输出；点节点在下方发任务、看对话记录；平移、缩放、小地图 |
| 5 | 内容节点和编辑 | 新建和上传文本、图片、视频、音频节点；连线作参考；框选、打组、复制粘贴、撤销重做；机器人交出的文件成为节点；机器人能读写画布 |
| 6 | 生成和项目配置 | 项目全局配置；从 MCP 取模型列表；分镜节点；图片节点、分镜节点、视频节点和生成配置节点通过 MCP 生成；机器人触发生成 |

第 1 块改动的现有代码最多，因为要去掉模板库。第 4 到第 6 块是全新的。

## 风险和还没验证的事

1. **生成用的 MCP 服务器还没定。** MCP 本身没有"模型列表"这个概念，要靠服务器提供一个列出模型的工具。第 6 块先按文档里的约定做，只能用测试用的服务器验证；真正的服务器定下来后，对接这一层可能要返工。
2. **程序直接调用 MCP 工具。** 现在 MCP 工具是机器人在对话里调用的。程序自己调用一个用户配置的 MCP 工具这条路，我还没有在代码里确认是现成的。
3. **机器人会不会好好用画布工具。** 分镜机器人要把每个镜头做成节点，而不是只在回复里写一段文字。第 5、6 块要在测试实例里实际跑几次，调整工具说明。
4. **移植的量不小。** infinite-canvas 的画布页面是一个很大的文件，还依赖它的界面库和本地存储。要一边移植一边换掉这两样，第 4、5 块的工作量主要在这里。
5. **只能派给直接下级，可能太死。** 成员想问另一条线上的同事时问不了，只能经过上级。先按严格的做，实际用起来不顺再放宽。
6. **节点越做越多。** 一部剧几十集、每集十几个镜头，画布会很大。打组是第一步，以后可能要按集分画布。
7. **主机器人移出部门后的参谋长范围。** 它移到一般区域后，那里如果已有另一位参谋长，要定谁优先。第 1 块的实施计划里解决。
8. **去掉模板库牵涉的测试多。** 模板库、模板同步和建项目的测试要一起改。
9. **左侧隐藏后的未读。** 项目外的机器人有普通回复时，只靠"团队地图"入口上的圆点提示。
10. **和上游的差距变大。** 左侧和团队地图都是上游经常改的地方，以后合并上游更新会更费事。

## 怎么验证

按 `docs/verification/README.md`，每一块都在独立的测试实例上验证，不动你正在用的数据。整体要确认：

- 用同一支团队建两个项目，一个项目里机器人记住的事，另一个项目不知道。
- 改原机器人的人设和模型，两个项目里的分身都跟着变；在项目里直接改会被拒绝。
- 原团队加一个成员，两个项目都提示"团队有变化"，确认后才加入。
- 参谋长是主机器人的团队不能用来建项目，并说明原因。
- 主机器人原来在部门里的数据，升级后被移出，其余数据不变。
- 主机器人按需求提议建团队和项目，确认前什么都不建。
- 给成员指定第二个上级时，原来的上级被替换；会形成回路时被拒绝。
- 机器人把工作派给不是自己直接下级的同事时被拒绝。
- 画布上机器人之间只有一个根节点，每个机器人只有一个上级。
- 机器人回复后，文字出现在它自己的节点里；它交出的文件成为它右边的节点并连好线。
- 上传一张图片，连到一个视频节点，它出现在那个节点的参考图里；连到一个机器人，随任务一起发给它。
- 点机器人节点和点分镜节点，下方出现的面板不同。
- 改项目全局配置里的默认模型，没改过模型的节点跟着变，改过的不变；"恢复默认"后重新跟随。
- 在分镜节点上改参数后生成，交给 MCP 工具的参数和面板上的一致；分镜右边出现视频节点。
- 没有配置 MCP 服务器时，生成按钮不能点，并说明原因。
- 撤销和重做对新建、移动、连线、删除都有效。
- 机器人触发生成时，超过上限要用户确认。
- 以前按模板建的项目照常打开和使用。

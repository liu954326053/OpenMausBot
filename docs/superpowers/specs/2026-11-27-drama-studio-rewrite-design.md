# 漫剧工作室：全新架构设计

日期：2026-11-27 · 状态：讨论定稿，待复核
范围：产品边界、领域模型、流程、画布、运行时、UI、技术架构、验收
不包含：具体实施步骤；实施计划另写。

## 0. 决定摘要

| 决定 | 结论 |
|---|---|
| 产品 | 独立的漫剧创作软件，不基于 MagicBot 现有框架 |
| 代码 | 纯重写：UI、领域、画布、运行时全新；旧代码只读参考；开源库可用 |
| 分支 | `main` 保留为参考；开工前清理其他分支/worktree，只留 `main`；新分支开发 |
| 数据 | 不迁移旧数据；新数据目录与新模型 |
| 智能体 | 全局智能体库 + 项目指派；记忆按项目隔离；任务开始时快照 |
| 团队 | 团队预设：角色 + 默认流程 + 负责人 + 可选生成默认；可设默认；项目创建时快照 |
| 主 agent / 负责人 | 两级：主 agent 收需求、建项目；项目负责人计划、调度、汇报；用户可与任一 agent 对话 |
| 流程 | 类型化数据流图（智能体 ↔ 产物）；DSL 与画布是同一张图的两种视图；图是唯一真源 |
| 动态调整 | 运行中任务跑完；输入变化只标记下游过期；不自动重跑；重跑显式 |
| 画布 | WebGL2 场景；所有节点始终在场景中，不做数据裁剪、折叠或卸载；DOM 只做外壳与交互覆盖层 |
| 引擎 | 内置 agent 循环（自托管模型优先）+ 可选 Claude/Codex CLI 底座；能力契约一致 |
| 生成 | 出图/视频插件；全局默认 → 团队可选 → 项目 → 节点；节点显示实际服务与模型 |
| 技能/MCP | 全局库；在 agent 上声明启用；项目可临时加；不把所有已安装塞进上下文 |
| 权限 | 默认只在项目文件夹内读写与执行；技能脚本允许；离开项目文件夹需确认 |

## 1. 为什么重做

现有 MagicBot 是一个通用 agent 聊天平台：约 62 万行非测试源码，漫剧垂直只占约 3%；其余是手机接管、邮件、云电脑、浏览器、CUA、会议、语音、例行任务、主题、企业控制面等。漫剧功能长在这套平台之上，创作者看到的是 bot、线程、收件箱、引擎、模型、技能、MCP——平台的词汇，不是创作的词汇。

运行层面还有一处硬伤：`supportsWorkspaceFiles()` 把 `openai-compat` 排除在完整 agent 能力之外，而这正是自托管 LLM 的接入方式。被排除的引擎没有工作区文件、技能文件不投递，只剩聊天和少量工具。于是同一个产品里存在两种 bot：跑 Claude/Codex 的完整 agent，和跑自托管模型的降级聊天 bot。这不是命名问题，是能力问题。

结论不是继续做减法，而是按需求重做一个产品：只保留漫剧创作真正需要的骨头——智能体、技能、生成、项目、流程、画布、剪映草稿；其余从架构上不存在。

## 2. 产品边界

**是什么**

一个本地优先的桌面应用，用来创作多集漫剧：用户建项目、选团队、和主 agent/项目负责人定需求与流程，团队里的智能体沿流程产出剧本、角色、场景、分镜、镜头视频和成片；用户在无限画布上监工、审阅、调整，最后在剪映里导出成片。

**不是什么**

- 不是通用 bot 聊天平台，不做联系人、收件箱、在线状态、部门、房间。
- 不做手机接管、邮件、云电脑、浏览器自动化、CUA、会议、语音、例行任务、自定义主题、发布应用、企业控制面。
- 不做多人协作、云同步、账号体系；第一版是单机单用户。
- 不迁移旧数据；不兼容旧配置。

**核心循环**

新建项目 → 选团队（默认或自选）→ 主 agent/负责人确认需求与集数 → 负责人生成流程 DSL → 智能体沿图执行 → 画布审阅与调整 → 选定视频版本 → 生成剪映草稿 → 剪映导出成片。

**平台**

macOS 与 Windows 桌面应用；本地项目文件夹；本机剪映。第一版不覆盖 Linux 与移动端。

## 3. 名词与数据模型

| 名词 | 定义 | 关键规则 |
|---|---|---|
| 项目 Project | 一部剧，含 N 集；一个项目文件夹 | 创建时快照团队预设；不随团队后续修改自动变化 |
| 集 Episode | 项目内的一集 | 剧本、分镜、镜头、视频、成片都带集号 |
| 团队预设 TeamPreset | 可复用的配方：角色清单 + 默认流程 + 负责人 + 可选生成默认 | 可标记为默认；项目创建时选用；多个团队对应不同剧种/流程 |
| 智能体 AgentDefinition | 全局角色定义：名字、指令、模型/引擎、技能、MCP、工具权限、头像 | 不带记忆、不属于任何项目；可被多个项目引用 |
| 项目智能体 ProjectAgent | 智能体在项目里的指派：角色、覆盖项、记忆目录、可选集范围 | 记忆按项目隔离；每集专属角色按集隔离 |
| 技能 Skill | 可上传的包：SKILL.md、脚本、资源、manifest | 全局库；在 agent 上声明启用；项目可临时加 |
| 生成服务 GenerationService | 出图/视频插件实例：模型、协议、地址、密钥 | 全局默认；项目与节点可覆盖；节点显示实际选择 |
| 流程 WorkflowGraph | 智能体任务与产物组成的类型化数据流图 | 图是唯一真源；DSL 与画布都是它的视图 |
| 任务 Task | 某个智能体节点在某个作用域上的一次运行 | 记录输入版本、输出、状态；可重试 |
| 产物 Artifact | 流程产出的内容：剧本、分集、角色、场景、镜头、视频版本、成片 | 类型化、带版本；上游变化只标记过期，不删除 |
| 对话 Conversation | 主 agent、项目负责人、任一项目智能体的对话 | 是交互工具，不是产品首页；无社交语义 |
| 主 agent MainAgent | 工作室助理：收需求、建项目、选团队、跨项目查状态 | 不产出内容；不写剧本、不出图、不改画布 |
| 项目负责人 Lead | 项目级调度者：与用户计划、写/改流程、盯生产、重试、汇报 | 由团队预设指定；没有指定时主 agent 兼任 |

**存储**

- 项目文件夹是产物的真源：`project.json`、`source/`、`artifacts/`、`workflow.json`、`drafts/`、`.studio/`（任务日志、智能体记忆、索引）。
- 本地数据库（SQLite）保存项目索引、任务状态、消息、技能库索引、插件配置等；消息正文可以留在库中，产物一律落盘。
- 密钥不进项目文件夹；放系统钥匙串或加密存储，插件运行时才取。

**快照与删除**

- 项目创建时快照：团队角色、负责人、默认流程、可选生成默认、智能体引用。团队预设后续修改不影响已有项目；提供显式的“从团队更新”。
- 智能体定义是引用：修改全局定义影响之后开始的任务；运行中的任务使用开始时快照。
- 删除智能体：先列出引用它的项目，要求替换；不自动复制、不静默降级。
- 删除团队预设：已有项目不受影响（已快照）。
- 产物只软删除；恢复与撤销保留。

## 4. 智能体

### 4.1 定义

一个智能体是“角色 + 运行时配置”，不是聊天联系人：

- 名字、角色/头衔、头像。
- 指令/人设：这个角色怎么工作、输出什么。
- 模型与引擎：默认内置循环；可选 Claude/Codex CLI 底座。
- 技能集：从技能库里选，运行时加载。
- MCP 集：从 MCP 服务器里选，运行时挂载。
- 工具权限：文件、命令、网络、生成、对话。
- 不带记忆；记忆属于“项目 × 智能体（× 集）”。

### 4.2 作用域

- 全局库中的智能体可以被任意项目引用。
- 项目里的指派可以覆盖模型、追加技能/MCP、调整指令；覆盖项存在项目里，不改全局。
- 每集专属角色（分镜、后期等）用 `episode` 范围的项目指派；共享角色（编剧、角色设计、场景设计）用项目范围。
- 任务开始时对定义 + 覆盖项做快照，保证运行中的结果可复现。

### 4.3 记忆

- 记忆按项目隔离：`<项目>/.studio/agents/<指派 id>/memory`。
- 每集专属角色的记忆可按集再分层。
- 记忆只在这个项目里使用；不跨项目、不上传。
- 全局定义不保存记忆；需要沉淀的角色经验，由用户显式“保存为技能/指令”再进库。

### 4.4 引擎与能力契约

同一套能力契约，两种引擎：

| 能力 | 内置循环 | CLI 底座（Claude/Codex） |
|---|---|---|
| 模型调用/流式 | OpenAI 兼容 http/https，工具调用，文本工具调用兜底 | 由 CLI 负责 |
| 文件读写/搜索 | 项目文件夹内 | 项目文件夹内 |
| 命令执行 | 项目文件夹内，超时/输出/取消 | 由 CLI 工具负责，映射到同一权限 |
| 技能 | 目录 + SKILL.md + 脚本路径 | 同左 |
| MCP | 官方 SDK，按 agent 选择挂载 | 同左 |
| 权限 | 项目文件夹沙箱；离开需确认 | 同左 |
| 记忆 | 项目内读写 | 同左 |
| 产物写入 | 类型校验后写节点 | 同左 |

规则：

- 默认引擎是内置循环；引擎选择收在智能体高级设置。
- 能力缺失必须明示，不能静默降级；启动任务前做能力检查。
- CLI 底座不可用时，给出明确原因和替代路径，不假装成功。

### 4.5 权限

- 默认：在项目文件夹内读、写、执行；技能自带脚本允许执行。
- 离开项目文件夹的读/写/命令需要确认；确认一次可记住该路径/命令。
- 网络默认允许技能和命令使用；提供按智能体的网络开关。
- 密钥永不进入智能体上下文；生成服务在服务端取密钥。
- 所有命令、文件写入、外部访问留审计记录，便于排查和撤销。

### 4.6 对话

- 主 agent 对话：需求入口，跨项目。
- 项目负责人对话：计划、流程调整、状态汇报。
- 任一项目智能体对话：局部调整；它改自己的产物，负责人收到通知，下游标记过期。
- 对话是侧窗/面板，不是产品首页；没有收件箱、未读、在线状态。

## 5. 团队预设

一个团队是“做这类剧的配方”，不是组织：

- **角色清单**：每个角色指向一个全局智能体；可标一个负责人角色。
- **默认流程**：一段 DSL，定义角色、产物类型、依赖、作用域、闸门。
- **可选生成默认**：这类剧默认用的出图/视频服务与模型；不填就继承全局。
- **默认标记**：同一时间只有一个默认团队；新建项目预选它。

使用规则：

- 新建项目时选默认团队或其它团队；项目保存快照。
- 团队改了，已有项目不变；项目设置里可以“从团队更新”，显式确认后覆盖角色/流程（不覆盖已完成产物）。
- 团队地图保留：节点是团队预设，卡片展示角色和流程缩略图；不做部门、房间、在线状态。
- 删除团队预设不影响已有项目。

## 6. 流程：类型化数据流图

### 6.1 图模型

流程是一张有向图，节点有两类：

- **智能体节点**：一个角色的一次执行；声明输入产物类型、输出产物类型、作用域（全剧/每集）、提示与配置。
- **产物节点**：某一类内容的一次产出；带类型、集号、版本、生产者。

边表示“产物 → 消费它的智能体”。智能体产出新的产物节点。示例（用户给的例子）：

- 编剧产出：剧本、分集
- 剧本 → 角色设计 → 角色
- 剧本 → 场景设计 → 场景
- 分集 + 角色 + 场景 → 分镜 → 镜头
- 镜头 → 视频 → 视频版本
- 视频版本 → 后期 → 成片

### 6.2 类型与作用域

- 产物类型是封闭目录的第一版：`source`、`brief`、`plan`、`script`、`episode`、`character`、`scene`、`shot`、`take`、`final`。后续可扩展，但必须走类型注册。
- 智能体声明“接受哪些类型、产出哪些类型”；边只允许类型合法的连接。
- 作用域：`drama`（全剧一次）或 `episode`（每集一次）。每集节点消费同集产物 + 全剧产物；引擎按集 fan-out。
- 闸门：节点可标“人工确认后继续”，例如批量生成视频前。闸门不是默认，按团队流程配置。

### 6.3 DSL 与画布

- DSL 是图的声明式文本表示：节点、边、作用域、闸门、配置。负责人用它批量创建/修改流程；系统校验后实例化。
- 画布是同一张图的可视化与编辑界面。进入“流程编辑”模式后可以改上下游；类型不合法的连接直接拒绝。
- 图是唯一真源：DSL 编辑写图，画布编辑也写图；不存在两份流程。
- 项目创建时，团队的默认 DSL 生成初始图；负责人可以按这部剧调整；调整产生新的图版本。

示意（不是最终语法）：

```
agent script    role 编剧      reads [source]                    writes [script, episode]  scope drama
agent character role 角色设计  reads [script]                    writes [character]        scope drama
agent scene     role 场景设计  reads [script]                    writes [scene]            scope drama
agent board     role 分镜      reads [episode, character, scene] writes [shot]             scope episode
agent video     role 视频      reads [shot]                      writes [take]             scope episode
agent post      role 后期      reads [take]                      writes [final]            scope episode
gate video before generate
```

### 6.4 调度

- 任务就绪条件：所有必需输入产物存在，且没有过期；作用域匹配；闸门已确认。
- 就绪任务按并发上限执行；互不依赖的任务并行（角色/场景、不同集）。
- 状态：`waiting`、`ready`、`running`、`done`、`failed`、`stale`、`cancelled`。
- 成功：写产物节点（新版本），触发下游重新评估。
- 失败：标记失败，通知负责人；可重试；重试产生新版本，不覆盖旧产物。
- 并发与停止：项目级并发设置；停止会取消运行中任务，保留已有产物。

### 6.5 动态调整

- 运行中的任务让它跑完；图的变化不打断它。
- 输入变化（上游产物新版本、边被删除）只把下游标记为 `stale`，不自动重跑。
- 新增边：下游等待新输入；满足后变 `ready`。
- 重跑由负责人或用户显式发起；重跑记录新的图版本与输入版本。
- 所有图变更版本化；任务记录它使用的图版本，保证可复现和可审计。

## 7. 画布

### 7.1 原则

- **不做数据裁剪**：所有节点/边始终在场景图里；默认不折叠、不按视口删除、不卸载。折叠只能是显式用户操作，且不影响流程与调度。
- **只做绘制裁剪**：屏幕外像素由渲染器/GPU 裁掉，节点仍在场景中；平移时不会“从无到有”弹入。
- **画布是独立渲染器**：WebGL2 场景，不是 DOM 页面；应用外壳与交互覆盖层仍是 DOM。

### 7.2 渲染分层

1. **场景图**：节点、边、分组、坐标、层级、状态；唯一真源，服务端同步。
2. **WebGL 层**：背景网格、边、智能体节点、产物卡片、缩略图、状态、标签；批量绘制。
3. **DOM 外壳**：侧栏、顶栏、右侧面板、菜单、对话框、设置。
4. **DOM 覆盖层**：打开的对话窗、详情面板、输入框、视频控件；锚定到选中节点，按需挂载。
5. **可访问性镜像**：可见节点的隐藏 DOM 列表/树，供屏幕阅读器和键盘导航；画布本身不承担语义。

### 7.3 卡片渲染

- 图元：圆角矩形、边框、阴影、进度、状态点、徽标。
- 文本：用 Canvas 2D 预渲染成纹理（中文排版交给浏览器），按样式/宽度缓存；远景用简化文本或纯色块（LOD）。
- 图片：纹理；缩略图按需上传；纹理图集减少切换。
- 视频：可见时才解码成纹理；离屏保留最后一帧；限制同时解码数量与纹理内存。
- 长文本（剧本页、详情）：不在卡片里逐字排版，点开走 DOM 详情。
- 卡片外观可以接近现有 UI，但实现是渲染器图元，不是 HTML 卡片。

### 7.4 交互

- 命中测试在世界坐标里做（场景图 + 空间索引），不走 DOM。
- 相机：单世界变换；平移、缩放、吸附、聚焦；不触发 React 重渲染。
- 选择、悬停、拖拽、框选；拖拽只改节点位置，不改布局算法。
- “流程编辑”模式：允许改上下游；边必须类型合法；运行中的节点给出提示。
- 小地图、适应视图、回到选中节点。

### 7.5 性能预算

- 2000 节点 / 4000 边，平移缩放 60fps（目标机器：Apple silicon 与主流 Windows 独显/核显）。
- 压力夹具：300 / 800 / 1500 / 2000 节点；量 FPS、首屏、长任务、纹理内存、GC。
- 空闲时按需渲染；交互时连续渲染；避免每帧分配对象。
- 降级：WebGL 不可用时给 Canvas 2D 渲染器或列表视图，并明确提示；不静默黑屏。

### 7.6 风险

- 中文文字与排版是最大风险；需要字体/纹理缓存与 LOD，不以 DOM 文本作依赖。
- 可访问性靠镜像层，测试要覆盖键盘与屏幕阅读器主路径。
- 视频纹理与解码数量受限；离屏只保留最后一帧。
- 视觉回归和性能基准要进 CI；否则容易在迭代中退化。

## 8. 运行时

### 8.1 内置 agent 循环

- 支持 OpenAI 兼容的 http/https 端点（自托管模型优先）。
- 工具调用循环：模型 → 工具 → 结果 → 模型；流式输出；可停止。
- 文本工具调用兜底（模型把调用写在文本里时解析）；重复调用保护；上下文压缩。
- 工具集：文件、命令、技能、MCP、产物读写、对话。
- 每次任务：系统提示（角色、项目、任务、输入产物、输出契约、技能目录）→ 循环 → 校验输出 → 写产物 → 事件。
- 失败分类：网络、鉴权、工具错误、输出不合法、超时、取消；给负责人可读的原因。

### 8.2 CLI 底座

- Claude/Codex 等 CLI 作为可选引擎；同一能力契约；同一项目文件夹与权限。
- 适配层负责：启动、提示、工具事件映射、输出收集、取消、错误翻译。
- 能力矩阵在 UI 明示；不可用的能力不给入口。

### 8.3 技能

- 技能库：zip 上传，校验 manifest、SKILL.md、文件数量/大小、路径穿越、符号链接。
- 目录结构：`SKILL.md` + 脚本/资源；技能工具给模型目录、说明和绝对路径。
- 在智能体上声明启用的技能；项目可临时追加；运行时只加载声明 + 项目追加的集合。
- 脚本在项目文件夹内执行；需要离开文件夹时走权限确认。
- 技能可以带参考文档；按需读取，不整包塞上下文。

### 8.4 MCP

- 服务器配置：名称、传输方式（stdio/http）、命令/地址、鉴权、工具列表。
- 在智能体上声明启用的服务器；项目可临时追加。
- 工具按需挂载；工具面过大时提示，不无限扩张。
- 生成不走 MCP；出图/视频走插件，减少一层。

### 8.5 生成服务

- 插件协议参考现有 `plugin.json` 的能力声明：模型、能力、请求映射、状态映射、配置字段、密钥。
- 安装：zip，校验大小/文件数/路径；启用/禁用；删除连同配置与密钥。
- 默认：全局默认出图/视频插件 + 默认模型；团队可选一套；项目可覆盖；节点可覆盖。
- 解析顺序：节点 → 项目 → 团队快照 → 全局默认 → 无（报错并指向设置）。
- 节点上显示“将使用哪个服务/哪个模型”；生成失败给出服务端可读原因。
- 并发、重试、取消由生成队列负责；结果落到产物节点。

## 9. 主 agent 与项目负责人

**主 agent（工作室助理）**

- 全局一个；收需求、建项目、选团队（默认或自选）、把项目交给负责人、跨项目查状态。
- 工具面只包含管理类：建项目、选/换团队、列智能体/技能/生成服务、启动/暂停/重试、查状态、汇报。
- 不给内容工具：不写剧本、不出图、不改画布、不跑生产任务。

**项目负责人（Lead）**

- 项目级；团队预设指定；没有指定时主 agent 兼任。
- 与用户确认需求、集数、原作、风格；生成/修改流程 DSL；启动生产；盯状态；失败重试；向用户汇报。
- 产出 `brief` 与 `plan` 产物；不写剧本、不做设计、不出图。
- 可以直接和用户对话；用户也可以直接找任一角色智能体。

## 10. UI 信息架构

**首页**

- 项目列表（卡片：封面、集数、进度、最近活动）。
- 主 agent 对话入口（新建项目、问状态）。
- 新建项目。

**项目**

- 顶栏：项目名、集选择、团队、设置。
- 画布：全部节点/边；流程编辑模式；小地图；适应视图。

- 点智能体节点：对话侧窗。

**库**

- 智能体库：列表、编辑、测试对话；模型/引擎、技能、MCP、权限。

- 生成服务：插件列表、模型、默认值、密钥。

**没有**

## 11. 技术架构

- **桌面**：Electron + React + TypeScript；全新应用骨架，不 import 旧应用代码。
- **本地服务**：Node 进程（可与 Electron 主进程同进程或子进程）；类型化 RPC + 事件流；SQLite；项目文件夹。
- **渲染**：WebGL2 画布（PixiJS 8 作为候选底座，或自研 renderer）；DOM 外壳与覆盖层。
- **模块边界**：项目、团队、智能体、技能、生成、流程引擎、运行时、对话、文件、设置；每个模块有清晰接口，可单独测试。
- **事件**：任务/产物/图变更走事件流；渲染器增量更新；断线重连后全量快照。
- **安全**：本地回环；密钥加密/钥匙串；项目文件夹沙箱；zip 安装校验；命令审计。
- **打包**：electron-builder；macOS/Windows；自动更新；签名/公证按平台。
- **测试**：单元（vitest）、集成（Node）、UI（Playwright/Electron）、性能基准、视觉回归；全部用隔离夹具，不碰真实项目。

## 12. 分支与实施策略

- `main` 保留为现有产品的参考；不删除、不改历史。
- 开工前：处理 `main` 未提交改动；移除 40+ 个 worktree；删除除 `main` 外的本地分支；确认只剩 `main`。
- 从 `main` 新建开发分支（名字实施时定，例如 `studio`）。
- 纯重写：新分支上的新应用不 import 旧应用代码；旧代码只读参考；开源库可用。
- 旧代码在分支上的去留：实施计划里定；推荐把旧应用标记为 `legacy/` 只读参考，新应用放独立目录，构建与发布只指向新应用；稳定后再删旧目录。
- 不迁移旧数据；新数据目录、新配置、新密钥。
- 实施按里程碑拆计划：脚手架与外壳 → 运行时与技能/MCP → 流程引擎与 DSL → WebGL 画布 → 生成服务 → 团队/项目/主 agent/负责人 → 端到端与性能。

## 13. 验收

**功能**

- 建团队预设（角色 + 默认流程 + 负责人），设默认。
- 建项目（选团队、集数、原作），项目快照正确。
- 主 agent 收需求、建项目；负责人生成流程 DSL、启动生产。
- 智能体沿图执行；产物按类型落节点；并行/按集 fan-out 正确。
- 动态改上下游；运行中任务不被打断；下游过期标记；显式重跑。
- 出图/视频插件安装、默认值解析（全局→团队→项目→节点）、节点显示实际服务。
- 技能上传、按 agent 启用、脚本执行；MCP 挂载。
- 选定视频版本；剪映草稿生成；导出路径可用。
- 引擎切换：内置循环与 CLI 底座能力一致；缺失能力明示。

**性能**

- 2000 节点 / 4000 边，平移缩放 60fps；300/800/1500/2000 夹具全部通过。
- 首屏、交互延迟、纹理内存、GC 在预算内；无节点弹入弹出。
- WebGL 不可用时有可用降级，不黑屏。

**质量**

- 键盘可达；屏幕阅读器主路径可用；减少动态效果；浅/深外观。
- 项目文件夹沙箱生效；离开文件夹需确认；命令/文件写入有审计。
- 测试全部隔离；不读写真实用户数据。

## 14. 风险与开放问题

- **中文文字/排版**：WebGL 卡片文字是最大技术风险；需要字体纹理缓存、LOD、长文本走 DOM 详情。
- **可访问性**：WebGL 无 DOM 语义；镜像层要覆盖主路径，且不能成为性能负担。
- **视频纹理**：解码数量与内存；离屏只保留最后一帧；不同 GPU 的兼容性。
- **内置循环质量**：自托管模型的工具调用可靠性参差；需要文本工具调用兜底、重试、窄工具面。
- **流程引擎**：动态图、并发、过期传播、版本化是复杂度中心；要先把状态机与事件定死。
- **剪映**：macOS/Windows 的草稿路径与版本差异；需要真实样本验证；导出仍由用户在剪映完成。
- **工期**：纯重写 + WebGL 是最大投入路线；按里程碑交付，每一步可验收。
- **开放问题**（实施前定）：DSL 的最终语法；产物类型的完整目录；网络默认开关；旧目录在分支上的去留。
